## 目标
只改动 Love for NAI，不修改 NewAPI 源码。新增“图包额度”购买与消费：每包扣除用户 **$200.00 NewAPI 余额**，获得 **400 AFF 图包额度**；图包额度生成时最多 **10 张/分钟**。生图扣费顺序按已确认的决定：**图包额度 → 个人 AFF → NewAPI 余额**。覆盖登录后的网页工作台和 LFN 内部 `/api/images/*` 入口；外部兼容 `/v1/*`、`/ai/*` 继续直接使用调用方自己的 NewAPI Key，不接入 LFN 图包。

## 账本与购买后端

1. 扩展现有 `src/lib/aff.ts` 的用户钱包 JSON（仍使用 `LFN_DATA_DIR/aff/{userId}.json`，不新建第二个互不协调的钱包文件）：
   - 保留 `balance` 作为个人 AFF。
   - 新增 `packageBalance` 作为已购买图包 AFF；旧账户缺字段时按 0 兼容。
   - 交易记录增加来源/类型信息，区分个人签到、邀请/管理员发放、图包购买、图包生成消费、退款；不改变旧交易的解释。
   - 导出统一的图像额度扣除/退款函数，在现有 per-user lock 内完成：先尝试从 `packageBalance` 扣，余额不足时再从个人 `balance` 补足；只有两者合计足够时才提交扣除，否则返回 `null`，让调用方走 NewAPI。返回 `packageCost`、`personalCost`、各自剩余余额和总成本，失败退款时按原来源精确返还，避免把图包额度退回个人 AFF。
   - 个人签到、邀请奖励、管理员调整仍只进入个人 AFF；图包购买只进入图包余额。
   - 不用最近 100 条交易记录作为购买幂等依据，增加持久化购买订单/请求 ID 记录（至少保存 `pending/completed/failed`、包数、400 AFF/包、$200/包和时间），防止按钮重复提交导致重复扣款。

2. 新增 LFN 购买服务/API（建议 `src/lib/image-packages.ts` + `src/app/api/image-packages/purchase/route.ts`，具体文件名可按现有风格落地）：
   - `POST` 只接受当前加密 session，不接受客户端 userId、价格或额度作为可信输入。
   - 服务端固定常量：`PRICE_USD_PER_PACKAGE=200`、`AFF_PER_PACKAGE=400`、`PACKAGE_RATE_LIMIT=10`、窗口 60 秒；包数默认 1，并限制合理的单次上限，避免异常大额请求。
   - 根据 `QUOTA_PER_UNIT` 把 `$200 × 包数` 转为 NewAPI 原始 quota 单位；当前默认是 `100,000,000 quota/包`。
   - 通过已有服务端 `LFN_ADMIN_TOKEN/LFN_ADMIN_USER_ID` 和 `adminHeaders()` 调用 NewAPI 的 `POST /api/user/manage`：`action=add_quota`、`mode=subtract`、`value=quota`、`id=session.userId`。客户端绝不接触管理员令牌。
   - 购买流程服务端化并幂等：请求先登记订单，NewAPI 扣款成功后才增加图包余额并标记完成；重复 requestId 直接返回原订单结果，不再次扣余额。上游扣款成功但本地落盘失败时立即尝试用同一管理接口补回 NewAPI 余额，并保留失败/待处理状态和清晰错误，避免静默吞款。
   - 若未配置 `LFN_ADMIN_TOKEN` 或 AFF Gateway 不可用，购买接口返回可理解的不可购买原因，不允许用户买到无法使用的图包。
   - 可增加购买接口的用户级限流，购买价格、额度、包数均以服务端计算为准。

3. 扩展 `GET /api/wallet`：
   - 返回个人 AFF、图包 AFF、两者总可用量，以及图包商品元数据/购买能力：`priceUsd=200`、`affPerPackage=400`、`rateLimit=10`、`purchaseEnabled`。
   - `aff.enabled` 不再无条件为 true，而是反映 AFF Gateway 是否真实配置；避免 Gateway 未配置时 UI 误显示 AFF 可支付。
   - 保留现有 `newApi`、签到和邀请兼容字段。

## 生图扣费链路

1. 修改 `src/app/api/images/operate/route.ts`：
   - 将现有 `trySpendAff` 换成新的“图包→个人 AFF”统一扣费函数。
   - 图包额度参与扣费时，按用户 ID 走独立的 10 张/60 秒滑动窗口；达到上限时跳过图包余额，允许本次继续尝试个人 AFF，再不足才走 NewAPI（限速只限制图包，不限制个人 AFF 或 NewAPI）。并发检查与余额扣除在同一用户锁语义下完成，避免两个请求同时绕过限速或超扣。
   - 如果图包和个人 AFF 合计足够，允许一次请求按来源拆分扣除；如果合计不足，两个本地余额都不动，整单回退 NewAPI。
   - 成功响应保留 `payment` 兼容值，并新增来源明细（package/personal/mixed/newapi）和最新个人/图包余额；生成失败、未返回图片、部分批次失败时按实际来源比例/批次精确退款。
   - 生成完成后继续保存历史，并确保部分成功的批次不会把图包退款错误记入个人 AFF。

2. 修改 `src/app/api/images/generate/route.ts`：
   - 接入同一套图包/个人 AFF 扣费和 10 张/分钟规则，确保 LFN 内部生成入口一致。
   - 同时修复现有 AFF 不足时仍把 NewAPI token 发到 Gateway URL 的 fallback bug：AFF 足额才使用 Gateway；AFF 不足必须使用 `newApiBaseUrl()`。
   - 保持失败退款和响应字段兼容，并返回新的来源/余额明细。

3. 不修改 `src/lib/compat-api.ts`、`/v1/images/*`、`/ai/*` 的外部直通语义；这些接口没有 LFN session，继续由 NewAPI 按调用者 Bearer Key 计费。
