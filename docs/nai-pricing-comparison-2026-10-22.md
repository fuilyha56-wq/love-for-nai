### NewAPI 的完整结算公式

```text
p = Gateway 返回的 prompt_tokens / input_tokens（图片通道会映射字段）
c = completion_tokens，本次生图为 0
E = billing_expr 在实际 usage 上的计算结果
Q = QuotaPerUnit = 500000
G = 有效分组倍率（优先 GroupGroupRatio 特例，否则 GroupRatio）
S = 每人民币的站内余额单位 = 200

分档表达式：quota = round_half_away_from_zero(E / 1000000 × Q × G)
按次固定价：quota = round_half_away_from_zero(ModelPrice × Q × G × n)
余额扣减 = quota / Q
人民币 = quota / Q / S = quota / 100000000
AFF 等值 = 人民币 / 0.005（仅对照，不会同时从 AFF 钱包再扣一次）

普通动态 E = p × 80000，p = 50A → 人民币 = A × 0.02 × G
V5 动态 E = p × 100000，p = 50A → 人民币 = A × 0.025 × G
动态系数的一般式 C = 每 Anlas 人民币单价 × S × 1000000 / 50
```

这里的 `n` 只用于按次收费的旧 Medium / Limit 模型；分档表达式中 p 已包含本次总动态 Anlas，不再乘输出张数。LFN 拆成多次上游请求时，每次独立结算。

NewAPI 当前界面把余额标为 USD，另有 `USDExchangeRate=7.3`；本报表人民币采用站内实际 `S=200` 口径，不使用 7.3 把余额数字当美元再换算。内部余额 450 = 本方案的 ¥2.25。

例：High 2048×1536 / 28 步，A=90，p=4500：

```text
E = 4500 × 100000 = 450000000
quota = 450000000 / 1000000 × 500000 × 1 = 225000000
余额 = 225000000 / 500000 = 450
NewAPI 人民币 = 450 / 200 = ¥2.25
LFN 首档 = 90 × 5 + 5 = 455 AFF = ¥2.275
```

## 四、Gateway 计价公式：修改前 → 修改后

### 修改前（已读取运行容器源码）

无参考图、强度 1、uncond_scale 1、单张动态生成时：

```text
P = max(width × height, 65536)
B = ceil(2.951823174884865e-6 × P + 5.753298233447344e-7 × P × steps)
V4.5：旧计费量 = B；旧 p = 50B
V5 High：旧计费量 = 2B；旧 p = 100B
```

旧 Gateway 将 V5 的“2 倍销售用量”作为 Anlas 返回；旧 LFN 日计费则从 B 按 ¥0.025 计价，所以两者用量不一致。新实现统一为官方用量。

### 修改后（一般式，含图生图、批量与参考图）

```text
P = max(width × height, 65536)
有效步数 s = Medium 为 14，否则取请求步数
k = Medium 为 1 / 1.06521739，否则为 1
B = ceil(2.951823174884865e-6 × P + 5.753298233447344e-7 × P × s × k)
m = V5（High / Medium）为 1.5，否则为 1
t = strength；未指定时 img2img 为 0.7，其他为 1
u = uncond_scale，默认 1
单样本生成量 a = ceil(max(2, ceil(B × m × t)) × u)

N = 本次样本数
D = 具备 Opus 抵扣资格且 P≤1048576、s≤28 时为 1，否则为 0
R = 参考图总数；H = 已编码 Vibe 数
Precise 参考附加量 = 5 × R × N
Vibe 参考附加量 = 2 × max(0,R-H) + 2 × max(0,R-4)
A = a × max(0,N-D) + 对应参考附加量

动态 usage p = max(1, 50 × A)
动态响应 completion_tokens = 0
```

D 由实际请求资格决定，不是所有账号或所有请求自动减一；priority 请求不按免费档处理。参考图附加量加在模型生成量之后，不再乘 1.5。已编码 Vibe 超过四张的使用附加费仍存在。

固定档是另一条分支：单次单张、面积 ≤1,048,576、有效步数 ≤28、允许的 generate / img2img / infill、非 priority、无付费参考附加条件时，Gateway 返回 V4.5 **p=0**、High **p=25**、Medium **p=18**。这些是固定档标记，不可除以 50 当作 Anlas。NewAPI 图片通道会把 p=0 钳位为 1，所以 V4.5 必须保留 `p<100` 归零分支。批量或有额外付费操作时走动态档；逐张发起的多个请求分别判断固定档。

普通画布上限为 3,145,728 像素、64 对齐；Limit 为 1,048,576 像素、最多 28 步、单次单张。单张生成 Anlas 上限为 140；最大面积 High 46 步是 140，47 步起拒绝。2048×1563 会超面积且未按 64 对齐，不作为合法规格。

独立工具另算 A：Vibe 编码每张 2；超分按输入面积四档 1 / 2 / 3 / 4；Director 沿用现有 5、背景移除 65。工具换 AFF 时普通 A×4、V5 A×5，不再叠加生图基础费。Director 上游工具成本本轮未重新付费核验。

## 五、LFN 每日阶梯：以线上持久化配置为准

**纠正前表：线上 V5 的阈值是 75 / 125 / 200；V4.5 当前只有首档。前表中的 50 / 100 / 200 是代码默认值，不是此刻线上规则。** 本次保留线上持久化规则，不覆盖成默认值。

```text
单张 LFN AFF = round4((基础AFF + (阶梯附加人民币 + A × Anlas人民币单价 × α) / 0.005) × β)
阶梯附加人民币 = max(0, 当前阶梯baseCny - 首档baseCny)
基础AFF：V4.5=1；High=5；Medium=1
Anlas人民币单价：普通0.02；V5=0.025
α=anlasMultiplier；β=totalMultiplier
最终人民币 = 最终AFF × 0.005
```

线上各 V5 档的 baseCny 都是 0.04，差额为 0，因此不会再额外收 ¥0.04。第二档同时配置 α=1.1、β=1.1，动态部分实际为 1.21 倍；后两档动态部分分别为 1.3225、1.44 倍。基础 AFF 只乘 β。以下忠实保留线上这两个倍率，不只展示其中一个。
