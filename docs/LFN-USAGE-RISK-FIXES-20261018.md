# 使用记录、生图输入和风控配置修复

本次承接已发布的风控与计费修复，处理使用记录付款筛选、清空生成张数崩溃，以及后台校验、草稿、发布、等级用户和高频申请开关的反馈。原计费口径见 [前次发布报告](LFN-RISK-UI-API-WATERMARK-20261017.md)。

## API 余额不足反馈的核对

用户提供的 10 月 18 日 01:40 日志返回 `lfn_insufficient_credits`，对应旧版明确禁止 NewAPI 回退的分支。修复该分支的前次版本于北京时间 03:36 启动，因此该日志早于修复上线。核对时持久化 `strictApiBilling=false`，保留的兼容 API 审计在该版本启动后没有新的 402。这个时间范围结论不等同于对全部后续上游错误作保证。

新增回归覆盖 AFF、图包均为零时的普通 V5、V5 limit、V4.5 limit：真实调用 NewAPI 生成端点，付款来源为 NewAPI，本地余额和本地日阶梯张数不变。这里的上游响应在测试中提供；未代用户发起生产付费生图，也未调用额度管理接口扣款。

## 使用记录的付款来源筛选

- 新增“付款”选项：全部、个人 AFF（含混合）、图包（含混合）、AFF + 图包、NewAPI 余额。与原通道来源分开，筛选写入 URL，切换时回到第一页。
- 服务器按当前登录账号读取本地请求摘要、审计和结算，合并 NewAPI 消耗记录后先筛选再分页。仅查 AFF／图包时直接读取本地数据，不额外查询 NewAPI。
- 较早的工作台审计没有付款标签，使用账号及请求 ID 精确关联既有结算单补充；不以时间或相同模型推断付款来源，不公开其他账号或风控证据。
- 混合支付请求同时属于个人 AFF 和图包筛选。消耗按实际渠道显示 AFF 或 NewAPI 显示余额，零费用明确显示 0，缺失费用显示未提供。
- NewAPI 读取沿用有界的每模型预取。达到上限时提示缩小时间范围，不把未加载记录数量当成当前筛选结果总数。NewAPI 暂时不可用时可显示本地记录，并提示当前数据范围。
- 补齐生图第一页普通及流式操作的最终付款标签、生成张数和实际 AFF 消耗；收到上游响应头时不提前将整个请求结算为成功，NewAPI 回退继续不累计本地阶梯。

## 清空数字输入导致页面崩溃

旧数字控件把空字符串转成 0，生成张数为 0 时计费预估抛出异常，导致整个页面进入错误页。现在输入草稿与有效数值分开：可以暂时清空重输，离开输入框或按回车时提交合法数值；空值和无效值恢复先前有效值，生成张数约束为 1–30 的整数。复刻布局的数字控件也使用相同提交规则，CFG 等字段仍可使用合法小数。

## 后台校验、草稿、发布与规则动作

反代原来使用 `$host` 转发 Host，丢失公网 `:41800` 端口。浏览器的 Origin 包含端口，同源保护因而拒绝正常 JSON。边缘配置改为保留 `$http_host`，显式覆盖转发 Host；同源检查和管理员权限继续保留。迁移脚本先备份，执行 nginx 配置校验后平滑重载，失败恢复原配置。

草稿保存后在配置页顶部显示服务器草稿提示、保存时间和备注，并提供直接加载入口。恢复草稿沿用当前版本号，避免仅因旧草稿版本号产生无意义的“待发布修改”。发布按钮会明确指出尚未修改或缺少原因；修改并填写原因后才向服务器提交，过期版本仍拒绝覆盖。

重复提示词、设备/IP 关联等辅助规则的独立动作仍仅为观察。界面改为直接显示其原因，明确证据规则保留可编辑的动作；只有运行模式为执行时才执行所配置动作。没有将辅助证据改为可单独封禁的证据。

## 等级用户与高频总开关

点击风险等级后，下方显示该已发布等级对应的已观测用户，支持用户名/ID搜索及每页 10 条。没有标记的已观测账号按正常等级显示；人工封禁账号在案件页查看。未发布的阈值编辑不会改动此列表，发布后重新加载。

新增 `trust.enabled`，后台位于“检测参数 → 高频授权”，名称为“启用高频申请与账号高频限制”，默认开启以兼容现有策略。

- 开启：保留当前账号令牌桶、在途限制和高频申请审批。
- 关闭：隐藏管理员“高频申请”二级菜单及用户申请表，不执行这套账号高频准入限制，也不接受新的申请或批准；系统原有限速、通道并发、内容和有效处置继续生效。
- 开关需要发布才生效；关闭功能不会改变余额、免费总额度或人工封禁。

## 按要求重新开始记录标记

独立远程脚本默认仅预览，显式应用时停止应用，先在私有数据目录备份目标文件，再清空历史风险案件、标记消息、提示词聚类、个人证据、自动处置和行为基线。人工封禁保留，资金、调用审计、图片历史、结算、计费策略和每日网络授权保留。写入失败会恢复原文件；同一重置编号重复执行不会再次清除新记录。

新观测起点单独记录，旧版累计调用观察只使用该时间以后的调用，避免保留的旧调用记录立即重新生成旧标记。应用重启后恢复现有授权，并从新的标记周期开始观察。私有备份不提交仓库。
