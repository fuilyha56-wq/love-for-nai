# 模型、参数与请求限制

## 先查自己的模型目录

外部用 `GET /v1/models`，旧客户端兼容 `GET /v1/model`；网页模型入口使用站内模型信息。账号分组、Key 模型限制、服务端点和运营开关会共同影响可用模型。

| /ai 原生名称示例 | /v1 别名示例 |
| --- | --- |
| nai-diffusion-5-full | nai-v5-full |
| nai-diffusion-5-curated | nai-v5-curated |
| nai-diffusion-4-5-full | nai-v4.5-full |
| nai-diffusion-4-5-curated | nai-v4.5-curated |

表格用于名称对照，不保证每个账号都拥有这些模型。其他 GPT 图像或 Google/Gemini 类模型如已接入，按目录的真实 ID 和模型能力使用，不能套用所有 NAI 字段。

## NAI 基本限制

| 参数 | 当前代码校验 |
| --- | --- |
| 宽、高 | 至少 64，NAI 必须为 64 的倍数 |
| 普通 NAI 总面积 | 不超过 3,145,728 像素 |
| Limit 模型总面积 | 不超过 1,048,576 像素 |
| steps | 普通请求 1–50；Limit 最多 28 |
| n / n_samples | 通用入口最多 30；模型、尺寸与上游可进一步限制 |
| 参考图 | Vibe 与精准参考等合计最多 12 张 |
| 请求体 | 最大 25 MiB，代理还可能设置额外限制 |
| 图像请求限流 | 默认每个 Key 每分钟 30 次；另受图包与上游限制 |

入口上限不是每个模型的批量承诺。NAI 界面按画面面积给出更小的批量范围，Limit 单批为 1；大尺寸、特定动作或成本上限也可能被拒绝。所有参数应以当前工作台和 API 校验为准。

## 步数、采样与节约档

节约档的参数由对应模型模式固定，不能只改模型名后仍保留标准档任意采样配置。当前节约模式采用固定 14 步等约束，负面预设与采样参数以工作台输出或服务校验为准。

Seed 为随机种子，固定后用于可控比较；参考图、模型版本与后端变化仍可能改变结果。CFG/scale、采样器与噪声计划只对支持它们的模型生效。

## 图像与蒙版

图生图使用 `image`，重绘还需 `mask` 和支持该动作的模型。NAI 蒙版尺寸与源图一致，白色重绘、黑色保留。原生请求可以用 base64 或协议支持的文件引用；OpenAI 编辑端点可使用 data URL 或 multipart。

超分输入必须 PNG，最大输入面积与生成面积上限目前相同；支持的超分模型单独校验。参考图不能无限追加，人物参考与 Vibe 总量及兼容组合需同时满足。

## 收到 400 或 429 时

400 优先核对最终请求中的模型、尺寸、步数、数量、动作和图片格式，先删掉复杂参考并用一张小图复现。429 先读取 `Retry-After`，若没有则按逐步增加的间隔退避。不要把提高并发当作解决限流的方法。
