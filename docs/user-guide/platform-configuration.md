# 管理员：平台配置与注册登录

管理员登录后进入[后台](/admin)。配置按注册与登录、服务接入、端点管理、额度与奖励、模型与签名、网络与存储、Gateway 运营拆分。页面保存成功后读取最新配置；不要把未保存的输入当作已生效。

## 注册与登录

注册总开关控制是否允许新建账号；密码登录、系统访问令牌登录、邮箱注册和邀请码注册按独立开关开放。注册页面只展示允许的方式，服务端会再次校验，直接请求接口不会绕过策略。

密码注册配置控制新账号是否必须设置密码；要求邮箱验证时，不同注册方式都必须按策略提交邮箱和验证码。关闭邮箱注册不等于关闭邀请码注册，反之亦然。

## 所有方式保留，但注册必须填写邀请码

在“注册与登录”页面的“注册门槛”区域，开启“注册必须填写邀请码（仅限邀请）”，点击“保存设置”。只需要修改这一个开关，密码登录、访问令牌登录、邮箱注册与邀请码注册等现有入口都可保持开启。

开启后，用户仍可选择邮箱注册，填写用户名、密码、邮箱和验证码，但必须额外填写有效的本站邀请码。该要求对所有注册方式生效，包括直接调用注册接口和未指定 method 的旧客户端；服务端在发送邮箱验证码与创建账号前都校验邀请码。

“允许使用邀请码注册”仅控制独立的邀请码注册方式是否开放。“注册必须填写邀请码”控制所有新用户的注册资格。即使关闭单独的邀请码注册入口，只要邮箱注册仍开放且强制要求开启，邮箱注册也必须填写邀请码；不需要关闭任何登录方式。

“允许新用户注册”和“允许使用密码注册”需保持开启，当前注册账号仍需用户名与密码。邮箱验证可照常开启，此时新用户同时提供有效邀请码、邮箱和验证码。

管理员可仅提交 `PUT /api/admin/platform/settings` 和 JSON `{"requireInviteCode":true}`，不会修改其他配置。公开 `/api/auth/policy` 中的同名字段通知注册页显示必填邀请码。关闭此项只取消全局门槛，选择邀请码注册方式本身仍需要有效邀请码。

保存后用退出登录或无痕窗口确认：已有登录入口仍在，邮箱注册表单显示必填邀请码，未填时不能获取验证码或提交注册。有效邀请码来自本站邀请体系，不是 NewAPI 图像 Key。

邮箱域名白名单按完整域名匹配，`gmail.com` 不自动包含 `sub.gmail.com`。开启白名单前至少填一个域名；可在关闭限制时提前编辑。阻止邮箱别名会检查加号地址和受支持的 Gmail 点号或 googlemail 别名。

NewAPI 账号邮件可由上游发送；本地账号或本站发送验证邮件需配置 SMTP 主机、端口、用户名、授权信息、发件地址与 TLS。不要只验证页面开关，还要用受控账号核对邮件实际送达。

## 服务与端点

| 分类 | 主要内容 | 验证方式 |
| --- | --- | --- |
| 服务接入 | 本地/NewAPI 账号服务、NewAPI 地址与管理凭据 | 登录与钱包读取 |
| 服务接入 | Gateway、NAI 原生、独立图像、OpenAI 兼容上游 | 配置后小图验证 |
| 端点管理 | 类型、adapter、名称、启用、优先级和专用配置 | 确认目标模型路由 |
| 额度与奖励 | 图包、AFF、分钟限制、签到与邀请、每日计费 | 报价、钱包与流水 |
| 模型与签名 | V5/V4.5 开关、PNG 来源签名 | 模型目录与验证页 |
| 网络与存储 | 出站代理、可信反代、HTTPS Cookie、远程历史 | 连接、真实 IP 与历史权限 |
| Gateway 运营 | 渠道、账号健康、计费覆盖 | 对应状态与失败诊断 |

保存上游地址与令牌后，还需在端点管理启用正确适配器。模型存在不保证每个工具已实现，分别验证生成、流式、重绘、超分和 Vibe 等所需动作。

秘密字段读取时掩码，保留掩码表示不更改；修改时输入新值。前端不应索取或展示上游真实账号秘密来解决第三方客户端登录问题。

## 注册登录接口

公开 `GET /api/auth/policy` 返回当前 provider 与 policy。`PUT /api/auth/register` 发送验证码，`POST /api/auth/register` 创建账号，字段按当前策略包含 username、password、method、email、inviteCode、verificationCode。

`method` 为 email 或 invite。密码登录 `/api/auth/login`、两步验证 `/api/auth/2fa`、系统令牌登录 `/api/auth/token` 仍受开关和账号 provider 限制。

## 管理接口

- `GET /api/admin/platform/settings`：读取脱敏设置。
- `PUT /api/admin/platform/settings`：JSON 局部更新，类型、范围和依赖会验证。
- `GET /api/admin/platform/endpoints`：查询端点。
- `POST /api/admin/platform/endpoints`：创建或更新端点。
- `PUT /api/admin/platform/endpoints`：按 id 更新。
- `DELETE /api/admin/platform/endpoints?id=...`：删除端点。
- `POST /api/admin/platform/batch`：最多 50 项 operations，支持 settings.update、endpoint.upsert、endpoint.delete、billing.replace。

批量按顺序执行，部分失败返回 207 和失败项，已成功的前序项不会整体回滚。所有管理接口需要管理员会话，普通图像 API Key 不能代替。

## 运营核对顺序

先保存服务配置，再启用端点与模型；检查价格与额度；用受控账号验证正常登录、出图和退款；确认反向代理覆盖真实 IP 请求头并配置受信代理；最后向用户发布当前可用能力和文档。价格与配置变化时应同步更新对外说明。
