# 图片历史、下载、签名与隐私

## 查找与继续创作

打开[图片历史](/history)，选择记录查看大图、生成参数和可用操作。需要继续修改时导入工作台或编辑器，先核对模型、尺寸和参考图是否仍可用。

工作台可能同时提供服务端记录与本机缓存。本机缓存按设备、浏览器和账户范围管理；清理浏览器数据会影响本机保存，换设备不保证同步。服务端历史需要有效登录与所属账号权限。

## 下载应该选择哪种方式

下载菜单按当前图片提供原图、含参数或移除元数据等可用方式。复用创作参数时保留原始 PNG；公开分享前确认是否包含不希望公开的提示词或元数据。

截图、社交平台转码、重新编码和去元数据可能移除生成信息或来源签名。下载一份参数副本并不自动公开到广场，公开投稿仍需单独提交审核。

## 来源签名与检测

当管理员开启 PNG 来源签名时，生成结果可带 LfN 签名及关联请求信息。在[图片溯源检测](/verify)上传图片查看签名有效性与可查询记录。

验证成功说明签名可被校验，不保证画面内容本身真实；验证失败也不能证明作品一定不是本站生成，因为图片可能已重新编码或移除元数据。历史记录是否仍在保留期也会影响可查询信息。

## 删除与公开作品

删除历史是对所选记录的真实删除，先确认下载了需要保留的内容。批量删除时按页面提示选择范围，不要把缩略图还在缓存误认为删除失败。

历史、广场投稿和外部导出的文件是不同对象。历史删除不应被理解为自动撤回所有已发布作品或删除别人已下载的副本；公开作品管理需走相应投稿或管理员流程。

## 相关站内接口

| 接口 | 用途与权限 |
| --- | --- |
| GET /api/history | 当前登录用户的历史 |
| GET /api/history/{id}/image | 按身份检查访问历史图片 |
| DELETE /api/history | 删除自己的历史，支持 1–100 条批量 ID |
| POST /api/images/verify-watermark | 按上传内容检测签名 |
| POST /api/images/metadata-strip | 移除图片元数据，按接口要求鉴权与上传 |

这些是站内 API，不能因为拥有图像 Key 就读取其他用户的历史。外部调用生成后应自行保存返回的图片和请求 ID，不要假设浏览器历史会永久保留所有结果。

## 使用记录与 IP

[使用记录](/usage)用于核对模型、时间、状态、支付来源与请求 ID。Anlas 可能来自实际上游报告、估算或未报告，不应把缺失信息当作零消耗。

管理员按权限可查看脱敏 IP 证据，完整 IP 查询需要原因并审计。历史上未记录或已过保留期的信息无法恢复。求助时提供必要的请求 ID 和时间，去掉 Cookie、API Key、参考图隐私和完整鉴权头。
