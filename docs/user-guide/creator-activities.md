# 管理员：创作活动、周榜与文档维护

## 创建活动

在后台活动管理设置名称、公开介绍、Markdown 规则、封面、启用状态、UTC 起止时间和优先级。投稿奖励、每人次数、活动总奖励次数与总 AFF 预算分别配置。

次数上限或预算为 0 表示不限制；投稿奖励为 0 表示不发 AFF。公开展示与是否启用是不同配置，关闭公开展示会隐藏入口，但不应被理解为自动改变已有的奖励资格规则。

## 日常任务

后台活动管理中默认新增独立的「日常任务」，同时保留已有活动。选择日常类型可配置初始 AFF、每日生成目标和奖励，以及 Gallery 每个日榜名次的奖励；可暂停、隐藏、删除或恢复。

默认报名领取 100 AFF，每个账号每个活动一次。报名后每天成功生成 3 张图片领取 50 AFF，批量请求按实际成功张数计数，同一请求重试不会重复累计。失败、无图、超分和标注不计；站内及接入 API 的服务器确认生成结果都可计入。请求按发起时的北京时间日期归属，跨日完成仍计入发起日。

每天北京时间 00:00 刷新生成进度与日榜。日榜只统计报名后、当日收到的有效点赞，每位作者以当日获赞最多的一张审核通过的 Gallery 作品参榜。自赞、已取消的赞不计，同赞按投稿时间较早、作品 ID 排序。默认第 1 名 150 AFF、第 2–4 名 50 AFF、第 5–10 名 20 AFF，每位作者每天最多一份排名奖。

日榜零点结榜后自动发放，服务每 30 秒检查一次，重启会补结算尚未完成的日期；已结榜名次和金额会保存，失败后按原记录重试。报名和生成奖励也使用唯一入账凭证，避免重复发放。报名金额在报名时、生成目标和奖励在当日首次成功生成时固定；日榜按结榜时配置固定。开始后的活动开始时间不可修改。

日常任务在创作者工作台显示报名状态、AFF 图标、生成进度条、今日排名及昨日奖励，不参与投稿奖励优先级或周榜结算。其奖励不会受其他活动预算影响。

## 资格和发奖

活动可要求全部指定标签、排除标签、允许评级和允许来源。标签按不区分大小写的精确匹配；所有条件都要满足。审核通过后只由优先级最高的匹配活动发投稿奖励，重复审核或重试不重复发放。

来源区分本站生成、本地上传、其他来源；评级支持全年龄/R13/R17/R18。审核员需同时核对内容与署名，不能只依据标签自动批准。

## 周榜

选择点赞、下载或导入使用数作为指标，设置最低计数、各名次奖励和是否每用户只占一个名次。UTC 周一 00:00 切周，自动结算上一完整 UTC 周；北京时间为周一 08:00。

指标相同时按作品创建时间与 ID 稳定排序。活动总预算同时约束投稿和周榜奖励，次数上限与预算是独立条件。预算不足、资格不符或未达到最低指标都可能不发奖。

## 活动管理 API

`GET /api/admin/creator-rewards?deleted=1` 返回活动、奖励记录、预算与自动结算状态。

POST 的 `action=campaign` 保存活动；DELETE 携带活动 id 软删除；POST 的 `action=restore-campaign` 与 id 恢复。

手动周结算 POST `{"action":"settle-weekly","week":"2026-10-12"}`，日期必须是 UTC 周一；`action=auto-settle` 用于自动补结算。手动派奖使用 userId、amount、description，均要求管理员会话。

## 在线文档发布

在文档 CMS 选择文章，修改标题、分类、摘要与 Markdown 正文。保存草稿与发布是不同操作，公开文档只显示 published 版本。代码块、表格、图片与外部链接都可使用，图片优先用站点可访问的资源地址并填写说明。

版本冲突时重新读取当前文档并合并修改，不能直接用过期版本覆盖。更新后检查桌面和手机的正文、图片、链接及搜索结果。不要在公开文档中放管理员令牌或真实用户 Cookie。

## 内置文档如何更新

本仓库的当前指南源文件在 `docs/user-guide/`，清单维护标题、分类、摘要与排序。运行 `node scripts/sync-user-docs.mjs` 生成供站内使用的内容；`--check` 检查两者同步。

内置文档通过 revision 更新。未被管理员手改的旧内置文档自动升级，并在数据目录保存升级前备份；管理员编辑过的内容不会被自动覆盖。需要这些文章跟随新版时，先备份 CMS 编辑内容再由管理员人工合并。

内置文档不能删除，自定义文档按 CMS 权限管理。新增或发布后由公开接口 `/api/docs` 返回，搜索同时覆盖标题、分类、摘要和正文。历史发布报告与价格快照留作审计，不应作为当前用户操作教程。
