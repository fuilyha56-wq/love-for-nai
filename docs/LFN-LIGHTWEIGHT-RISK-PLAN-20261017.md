# LFN 轻量风控方案

日期：2026-10-17。状态：折中后的实施方案，尚未修改运行代码或部署。

本方案作为当前建议的默认落地方向，取代[生成调用专项规格](./LFN-GENERATION-RISK-SPEC-20261017.md)中的全量实时分析安排。原方案保留为扩展需求；身份验证、权限、人工封禁、资金结算和反中转的基础边界继续保留。下文阈值和性能预算都是候选值，尚未实测。

## 1. 折中原则

采用“少量实时计数 + 明确规则 + 低频汇总 + 可疑账号按需检查”。

普通请求只检查已经生效的限制、账号速率/并发与少量计数；复用原有鉴权和扣费。浏览器不运行指纹 SDK、不采集 Canvas/WebGL/音频/鼠标轨迹、不增加心跳和遥测请求。普通生成不等待外部 IP 信誉、语义模型或历史分析。

本地部署文件 `compose.prod.yml` 将 LFN 容器上限设为 1 CPU、512 MiB；这是配置观察，不代表已确认线上配置、进程数量或剩余资源。以这一级别的资源约束设计，先减少全量 JSON 读写、历史遍历及无效重复请求。

## 2. 七类需求的轻量实现

| 需求 | 实时保留 | 低频或按需处理 | 省去的成本与边界 |
| --- | --- | --- | --- |
| 额度滥用 | 按资金单位累计近 5 分钟实际消耗、有效预留；原有余额/预算原子检查继续执行 | 每 15 分钟更新一次可信消耗基线，突增与新设备等信号组合复核 | 不逐请求重算 28 天分位；慢速协同套利识别减弱 |
| 行为异常 | 单账号最近 16 个 Prompt HMAC、连续重复次数、最近调用时间 | 按 6 个四小时时段累计分布，每 15 分钟对脏账号做简单偏差比较 | 无 embedding、语义相似度、JSD 或跨账号 Prompt 聚类；近义变体识别减弱 |
| 设备关联 | 首次登录设置随机签名 Cookie；记录新设备和切换 | 登录/注册时更新设备—账号关联；已知关系最多每小时合并一次活跃时间 | 无硬件/浏览器主动指纹；识别的是浏览器实例，清 Cookie 或复制 Cookie 可能绕过 |
| 内容风险 | 只累计已有审核或上游明确、受信的内容拒绝；保存有效已审次数 | 达到比例/频次阈值后建案件；人工或已有审核通道复核 | 不新增逐请求第三方审核；没有明确结果时显示未覆盖，不能声称全内容安全 |
| 调用频率 | 账号令牌桶、并发/队列上限；Key 可加更严限制 | 低频汇总异常趋势 | 不保存每次到达时间形成长数组；各账号限额按套餐设置 |
| 反复触碰边界 | 拒绝后新尝试次数、冷却截止时间、明确退避违背次数 | 反复确认违规后升级案件 | 不用模型分析请求序列；固定冷却不因拒绝次数无限续期 |
| 地区/代理/VPN | 查询本地已缓存标签；无标签即 unknown | 首次新来源/已可疑账号才排队查询；可完全关闭外部信誉查询 | 无逐请求远程查询；未接入供应商时无法可靠判断 VPN/住宅代理 |

简化评分为三个状态：正常、观察、临时限制。后台保留命中原因和各项计数，不计算每请求七维加权总分。设备、作息、重复 Prompt、地区/VPN 等弱信号只进入观察，明确超限或违规规则负责自动限制。

## 3. 普通请求做多少工作

请求路径：原有鉴权 → 有效限制缓存 → 账号令牌桶与并发检查 → 可选 Prompt HMAC/设备 Cookie 校验 → 原有资金预留 → 生成 → 更新计数与结算。

- 硬限制和资金检查必须在付费上游调用前完成，排队出队时再查有效限制。
- 正常请求仅按账号/Key 查有限个键，不扫描其他用户、历史事件或全部限流键。
- 固定长度计数桶记录最近 30 分钟，维护近 5/10/30 分钟小计。轮转只处理固定数量桶，最多 30 个，与历史请求数无关；计数和成本单位分别存储。
- 内容违规按独立操作去重。内部重试不重复计违规；真实到达请求仍消耗速率令牌，防止重复请求冲击资源。
- Prompt 复用已有规范化 HMAC，不保留原文；仅对业务已允许长度的文本计算一次。16 个摘要的比较是固定上限，重复只观察。
- 上游结果到达后更新成功/明确违规/故障计数。账本结算仍通过原有持久化事务或锁执行，不能为省性能改成最终一致的内存余额。

可以维护 5 分钟和 30 分钟的小计，但后台必须标明分钟桶精度；靠近边界的估算不能用作精确计费或严格滑动窗口保证。合同请求速率由已校准的令牌桶控制，费用硬上限由账本原子预留控制。

## 4. 设备与网络开销

设备 Cookie 使用服务端随机标识和签名，HttpOnly、SameSite，HTTPS 下 Secure；在登录响应中设置，退出登录时保留设备标识以观察换号。值长度目标不超过 100 字节，只随原有同源请求携带，不附加设备检测请求，也不每次重发 Set-Cookie。

未携带或校验失败时设备状态为未知/新实例，不能因此认定违规。API 客户端不要求安装 SDK，也不把无 Cookie 当恶意；用已有账号、Key 和会话约束。Cookie 可被清理或共享，设备关联只作辅助，不承诺识别物理设备。

设备—账号关系首次出现、新设备和切换立即更新；相同已知关系仅低频刷新活跃时间。每账号最多保留 8 个近期设备、每设备最多保留 16 个近期账号及各自 lastSeen，过期清理；超过容量显示“至少达到上限/关联过多”，不能展示伪精确数量或静默替换后声称关联减少。只对已鉴权或完成注册的真实主体建关联，不能接受客户端任意指定账号。

地区查询默认使用已有离线库，并按可信规范化 IP 缓存 24 小时；只查询首次来源或缓存过期的活跃来源，异步执行，首次请求不等待。VPN/代理信息有独立来源和 TTL：可选外部查询只针对新来源且已有异常的账号，单 IP 最多每 24 小时一次、失败负缓存 1 小时，全局限为每分钟 5 次、并发 1、超时 1 秒，队列上限 100。上限是候选配置，供应商要求优先。

同一 IP 的并发查询合并；队列满时跳过可选查询并标记 unknown，不拖慢生成。恶意来源可在现有边缘入口限速；代理/VPN/地区标签单独不永封账号。所有地址统一采用受信入口解析，不使用任意自报的 X-Forwarded-For、X-Real-IP 或 VPN 标签。

客户端收到 429 时根据 Retry-After 暂停既有生成重试，不增加风控轮询；恢复由下一次正常操作检查。风控后台仅打开时按需读取汇总，默认手动刷新，避免浏览器和服务器常驻轮询。

## 5. 少量规则即可覆盖主要风险

| 规则 | 起始候选条件 | 动作 |
| --- | --- | --- |
| 账号请求/资源超限 | 超过套餐批准的令牌桶速率、并发、排队或预留预算 | 当次拒绝/排队，给出明确重试时间；不计内容违规 |
| 消耗突增 | 近 5 分钟消耗超过套餐绝对门槛和可用可信基线 5 倍，同时出现新设备或明确异常 | 暂停新资金预留 15 分钟并记录原因；正常付费批量创作不能单凭消耗高被认定套利 |
| 反复明确违规 | 10 分钟内 ≥5 个独立明确内容拒绝，其中 ≥3 个新操作发生在拒绝反馈发出后 | 暂停相关生成能力 30 分钟 |
| 明确违规比例高 | 30 分钟有效已审操作 ≥20，明确拒绝比例 ≥40%，且反馈后 ≥3 次新的明确违规 | 暂停相关能力并复核，最长 24 小时 |
| 冷却期间密集重试 | 已鉴权、明确退避期限前，每分钟 ≥10 次新尝试，连续 2 分钟 | 对相关 Key/会话执行一次固定 5 分钟保护；不刷新已有内容暂停期限 |
| 可疑设备协同 | 同设备 24 小时 ≥5 个账号，并有服务器确认的协同领赠/消耗证据 | 暂缓相关待发奖励并建案件；设备数量单独只观察 |

费用基线每 15 分钟从可信按小时/时段汇总更新，至少 7 个活跃日和 30 次确认结算，异常样本隔离、延后 24 小时再纳入。缺乏基线时依靠明确的新账号/套餐预算，不做倍率处罚。不同资金单位各自比较，不把 AFF、图包和 Anlas 混加。退款修正原操作消耗，执行不明单独对账。

作息偏差用当前 6 时段占比与历史 7 个有效日占比作简单差值比较；近期不足 30 次或历史不足 100 次只显示样本不足。它只影响观察列表，不自动限流；基线低频更新且不扫描原始请求。

5xx、超时、余额不足、参数错误和普通 429 分开计数，均不进入内容违规分子。内容比例分母只计得到明确通过/拒绝的独立已审操作。未接入审核显示“未覆盖”，不能用“非拒绝”充当“已审通过”。高置信禁止内容的当次拒绝仍独立执行，不允许先违规几次。

同一事件不重复加分/建案；反馈前已在途的并发请求不算无视反馈；限制实例有固定 expiresAt。到期有限恢复，不能靠用户刷新页面或自动重试无限续封。尚未实现的验证渠道不能作为上线恢复条件；轻量版默认用有期限限制、现有重登录和管理员复核。

## 6. 存储与进程数的折中

**确认单服务进程时：** 速率、短窗观察计数和摘要放在进程内有界缓存；复用现有持久存储保存政策与有效限制，不为此强制新增数据库、独立队列和分析集群。实际账本、退款和权限仍持久化。容器只有一个不等于一定只有一个处理请求的进程，上线前核对运行模式。

内存状态初始上限建议：2,000 个活跃账号、4,000 个速率 Key、4,000 个网络缓存项；设备缓存按关联边数另设上限。它们是待压测调节的容量值。使用惰性过期与定时游标分批清理，每批最多 100 项，不能每次请求遍历整个 Map。

已生效限制保存在独立状态表/小型追加日志，激活、解除和到期变更才持久化；激活先更新内存立即生效，再在确认持久化后返回处置成功。重启恢复限制完成前不接收付费生成。短窗观察计数允许重启丢失，明确接受这一弱化；若重启后额度突增暂时无法判断，使用保守启动速率与原有预算上限，不能把内存计数用于唯一资金保护。

缓存满时先分批回收过期项，停止可选观察/提示词缓存；对无法安全登记速率状态的新调用方返回短暂 429/503。不能淘汰仍生效的限制以放行，也不将容量不足记成账号违规。

**多进程/多副本时：** 账号速率、并发、有效限制和需要立即生效的违规计数改用现有共享存储。若已有 Redis，每次准入目标为一个有界原子脚本/事务往返；完成时再做一次原子更新。pipeline 只节省往返，不能替代检查与扣减的原子性；脚本只操作有限个键，不能扫描全库。资金操作继续采用账本事务，不能声称它与 Redis 跨存储天然原子。

没有共享存储时，轻量内存版本只支持一个处理准入的服务进程；不能在多副本上宣称全局限额正确。不为提速长时间缓存可变余额和账号限制；策略更新本进程立即生效，多进程使用同一准入状态或可靠失效通知。

## 7. 审计、写盘与故障退化

当前代码的风控读取策略、使用记录、案件/事件与聚类，并重写多份 JSON；`request-audit.ts` 也会写入索引和使用文件。现有限流器每次检查会遍历所有 Key。若保持这些路径再叠加新计数器，不能保证净性能改善。

落地时必须将准入与历史列表查询分离：

1. 策略与有效限制启动加载，变更后更新缓存；准入不读取全量案件/历史文件。
2. 频率计数采用令牌桶/固定容量桶，不再按请求遍历全部用户或写使用历史以求计数。
3. 正常诊断事件先进入有界内存队列，10 秒或 100 条合并一次追加写入，避免全量 JSON 重写；按时间/大小轮转，后台分析使用增量游标。队列最多 2,000 条，重复冷却拒绝每账号每分钟只写一条摘要并累计次数。
4. 资金、退款、权限变更、限制激活/解除和明确违规证据不采样、不只靠易失队列。持久化小型必要记录，诊断详情才允许合并/丢弃。
5. 队列饱和时先舍弃普通成功诊断细节并累计丢弃数；仍无法保存必要证据时，对受影响受保护操作返回服务不可用，不能把丢失证据标成已保存。
6. 单进程后台每 15 分钟处理本周期有变化的账号，按固定批次推进，每批后让出事件循环；没有必要先部署独立消息队列。任务重跑按游标/事件 ID 去重。

不增加图片二次下载、不为风控上传 Prompt 原文/图片到新服务、不增加内容图像解码。已有必审流程继续执行；新的分类器与多模态审核留待有资源和业务要求时单独评估。

## 8. 性能预算与验收

下面是实施时要验证的目标，不是现有效果保证：

| 项目 | 初始目标 |
| --- | --- |
| 浏览器新增 JS、后台任务、独立风控请求 | 0；设备 Cookie 随现有请求携带 |
| 普通请求同步外部信誉/模型调用 | 0 |
| 风控增量延迟，确认单进程本地缓存命中 | P95 ≤2 ms；测试包含摘要计算与计数，不含原有鉴权/账本/上游 |
| 共享存储部署的准入往返 | 目标 1 次有界原子操作；延迟按同机房实测单列，不承诺 2 ms |
| 新增风控状态内存 | 候选目标 ≤24 MiB，在上述容量内实测，含对象、索引和队列；超过则先减少可选缓存 |
| 普通调用的风控写盘 | 无逐请求全量 JSON 重写；诊断批量追加，必要状态单独持久化 |
| 可选外部网络查询 | 默认可关闭；启用时全局 ≤5 次/分钟，并发 1 |
| 1 CPU / 512 MiB 下总开销 | 同等负载比较 CPU、RSS/堆、GC、事件循环延迟、磁盘写量、吞吐和失败率，超过预算先关闭可选观察能力 |

使用本地模拟上游回放，避免付费生成干扰；分别测试正常高频、热账号、不同账号高基数、连续拒绝、冷启动、缓存/队列满和进程重启。延迟预算在正常与拒绝路径分别测 P50/P95/P99；容量测试报告实际并发和请求速率，不能只报空载微基准。

功能验收保留：换端点/出口不绕账号限额，普通故障不算违规，固定冷却不续封，设备/VPN 单项不永封，重启不丢有效限制，多进程不能突破共享上限。明确输出放弃实时语义、完整设备指纹和低频跨账号图谱后存在的检测缺口。

## 9. 推荐实施顺序

第一步先优化现有风控读写与限流路径，再加账号级令牌桶、结果分类、固定冷却和消耗桶；这些对成本和异常重试最直接。

第二步增加登录时随机设备 Cookie、有上限的设备关系及现有明确内容拒绝计数。第三步再按实际收益打开低频基线和可选网络信誉，不一次启用全部检测。

依据：[Redis INCR 官方文档](https://redis.io/docs/latest/commands/incr/) 给出常数时间计数及限流模式，并指出计数与过期分离的竞态问题，可参考其原子脚本方式。本文缓存容量、处理频率、阈值与性能预算均为 LFN 设计建议，不是该资料提供的生产参数。
