# LFN 审核、IP 去重与代理链路封控改进方案

日期：2026-10-17。状态：设计提案，尚未实现或部署。依据为当前工作区代码静态检查，未核验线上配置、线上记录或真实用户行为。

策略强度和实施优先级已由 [高强度账号安全与反中转方案 V2](E:/love-for-nai/docs/LFN-ACCOUNT-SECURITY-RISK-V2-20261017.md) 更新；本篇继续作为 IP 去重、地址信任、范围查询及链路结算的基础说明。

目标：同一账号重复使用同一 IP 时，IP 历史始终只显示一行；管理员能按地址范围和业务范围审核；对站内操作、外部 API、代理调用及上下游转接执行一致且可追溯的封控。

**1. 当前实现与需要补齐的地方**

| 当前机制 | 代码中看到的情况 | 改进方向 |
| --- | --- | --- |
| IP 证据 | `risk-ip.ts` 已按 IP HMAC 复用全局证据，并维护账号关联 | 保留聚合思想，用数据库唯一约束保证多进程并发去重 |
| 用户 IP 历史 | `user-ip-history.ts` 将 LFN 证据与 NewAPI 登录、调用按 IP 聚合 | 统一 IPv6 规范化、来源身份与可信等级，避免混入服务器出口地址 |
| 登录计数 | `getSession()` 读取有效会话时也调用 IP 记录函数 | 分开统计真正登录、会话活跃、业务请求；读取会话不等于一次登录 |
| 客户端 IP 提取 | IP 证据优先 `X-Real-IP`；请求审计和限流的处理不同；信任开关读取来源也有差异 | 全模块只消费同一份由可信入口生成的请求上下文 |
| 边缘转发 | 仓库 Nginx 配置覆盖 `X-Real-IP`，但追加 `X-Forwarded-For` | 明确可信边界，禁止其他模块把客户端自填的最左地址用于封控 |
| 摘要关联 | 审计 IP 使用 SHA-256，IP 证据使用 HMAC | 使用统一 `ip_id` 关联；普通 SHA-256 不能视为 IP 匿名化保障 |
| 封禁 | 现有风控动作支持账号、邀请链，本地接口明确未同步 NewAPI | 增加 Key、会话、代理主体、IP、网段、能力范围和上游通道封控 |
| 入口覆盖 | 站内、OpenAI 兼容、NAI 原生、个人供应商及透明回退走不同路径 | 在选通道、扣费和转发前执行公共准入检查，建立入口覆盖清单 |
| 证据持久化 | 多个核心模块使用 JSON 和进程内锁；IP、请求等有数量上限 | PostgreSQL 保存事实与动作，Redis 保存共享限流；禁止静默截断后宣称记录完整 |
| 风险累计 | 多类信号可重复累加，案件分数缺少统一时间衰减 | 对同一规则事件去重，按窗口衰减，并区分观察与执行 |

以上是本地实现观察，不能据此断言线上重复 IP 的具体根因。上线前应使用脱敏样本复现，检查是否来自 IPv6 文本差异、账号身份映射、重复采集或展示列表。

**2. IP 历史只记录不同地址**

产品规则固定为：**一个账号在保留期内使用同一个规范化 IP，只保留一条账号与 IP 的关联记录。A → A → B → A，列表最终为 A、B 两行。**

| 账号 | 地址 | 首次出现 | 最近出现 | 成功登录 | 业务调用 | 活跃会话 |
| --- | --- | --- | --- | --- | --- | --- |
| 用户甲 | 203.0.113.8 | 首次时间 | 最新时间 | 12 | 340 | 2 |
| 用户甲 | 198.51.100.9 | 首次时间 | 最新时间 | 1 | 8 | 1 |

重复访问仅更新最近出现时间和对应计数，不追加一条 IP 历史。默认页面显示“2 个不同 IP”，登录次数和调用次数分别展示。

账号身份使用 `(tenant_id, identity_provider, external_user_id)`，再映射内部 `account_id`；避免本地账号与 NewAPI 的相同数字 ID 被合并。

建议数据结构：

| 实体 | 唯一性与主要内容 |
| --- | --- |
| `ip_entities` | 同租户、同规范地址一个稳定 `ip_id`；规范地址加密保存，HMAC 用于精确匹配，带密钥版本 |
| `account_ip_relations` | 唯一 `(account_id, ip_id)`；首次/最近出现、登录次数、请求次数、来源集合 |
| `ip_observations` | 来源事实；包含 `event_id`、IP 角色、可信级别、采集服务、时间、关联链路 |
| `account_ip_daily_stats` | 唯一 `(account_id, ip_id, date, metric)`；支持指定日期内的准确计数 |
| `sessions` | 每个会话独立存在；同 IP 的两个会话依然能分别撤销 |
| `request_traces` / `request_attempts` | 一次业务操作及其多次上游尝试分开记录 |

实现要求：

- IPv4、IPv4 映射的 IPv6、IPv6 大小写及压缩写法统一解析成规范地址；校验和格式清洗由一个函数承担。不能仅对 IPv6 转小写。
- 端口和方括号只在明确的传输格式中解析；拒绝混杂文本、无效地址和过长转发头。无可信地址时标为“未知”，不创建一个供所有未知用户共享的 IP 身份。
- 数据库唯一约束与原子 upsert 保证并发下仍只有一条账号/IP 关系；事件使用唯一 `event_id` 去重，同一次请求被多个模块处理不重复计数。
- 成功登录只在认证完成并建立会话时计数；令牌刷新、读取 Cookie、刷新页面不增加成功登录次数。
- 同一实际 IP 被多个用户使用时，IP 实体可以共享，但每个账号各有一条关系；全局展示所有关联账号，不能被最后一个使用者覆盖。
- 同账号/IP 的登录来源与直接调用来源合并为来源集合。被判定为代理出口、LFN 出口或上游连接地址的观察，保留其角色，不能冒充终端客户端地址。
- 详细登录事件、会话和调用审计继续独立留存；它们是安全追踪依据，不作为重复 IP 行追加到列表。
- 跨 LFN、NewAPI 和 Gateway 的同一调用以可信链路 ID 关联后计一次业务调用；历史缺少关联 ID 时分来源显示计数并标“不可精确合并”，不把相加或取最大值伪称精确结果。
- HMAC 密钥轮换通过旧版别名匹配、迁移和双读过渡复用稳定 `ip_id`；直接换密钥重新散列会重新产生重复地址。

**3. 可查看范围与 IP 过滤**

“可查看范围”同时包括查询条件和管理员的数据权限。两个层面都由服务端执行。

| 筛选维度 | 建议能力 |
| --- | --- |
| 时间 | 最近 24 小时、7 天、30 天、自选起止时间；时间统一存 UTC，后台按 Asia/Shanghai 显示 |
| IP 范围 | 精确 IPv4/IPv6、CIDR 网段、起止地址；起止地址必须同地址族且顺序有效 |
| 地址角色 | 用户访问地址、合作代理出口、边缘入口、LFN 出站、Gateway/上游连接地址 |
| 数据来源 | 成功登录、失败登录、会话活动、站内调用、OpenAI 兼容、NAI 原生、NewAPI、Gateway |
| 可信程度 | 可信入口观测、已认证代理声明、未验证声明、历史来源未知 |
| 关联账号 | 当前账号、同 IP 的多个账号、同代理主体；邀请关系独立展示 |
| 业务 | 模型、操作、Key、代理主体、上游渠道、支付来源、请求结果 |
| 风险 | 待审核、观察、限流、临时限制、封禁、已申诉、误报 |
| 网络归属 | 国家、省市、ASN、运营商；缺失或过期数据明确显示未知 |

列表提供“按账号去重”和“全局 IP 去重”两个视图。网段聚合为单独的分析视图，不能把同 /24 或 /64 内的不同 IP 当成同一个 IP 去重。

筛选示例：“近 7 天，203.0.113.0/24，外部 API，共享账号数 ≥ 3，只看可信入口观测”。所有数量、分页和导出都在权限与筛选条件生效后计算，禁止仅筛选已加载的一页。

时间口径明确区分“该时间内出现过的不同 IP”和“该时间内登录/调用次数”。按日期查询从事件或日汇总取数，不能用累计次数代替窗口内次数。

权限建议：普通用户只能查看本人安全记录；审核员查看被授权用户组或案件的脱敏数据；风控管理员可按职责设置限制；完整 IP 查询与导出作为独立权限，填写用途并留下操作者、查询条件、结果数和案件 ID。通过查询或计数推断地址也属于访问敏感数据，不能绕过权限。

范围查询落地：第一阶段可对已授权、受时间约束的候选记录在服务端解密匹配，设置资源预算，超出预算转异步任务，不静默返回不完整结果。规模扩大后使用受限 schema 中的 `inet`/`cidr` 查询索引；该索引本身含可读取的地址，必须明确采用数据库角色隔离、存储加密、备份保护和访问审计，不能宣称仍是字段级密文。若要求数据库也看不到地址，则改用单独设计的前缀 HMAC 索引，支持的网段精度及查询成本需专项评估。

**4. 统一可信 IP 提取，防止伪造与混入中转地址**

入口生成统一请求上下文：`trace_id`、`account_id`、`credential_id`、`peer_ip_id`、`observed_client_ip_id`、`claimed_client_ip_id`、`ip_trust`、`ingress_id`、`agent_id`、`policy_version`。

- `peer_ip` 表示当前网络边界直接连接者。Next.js 路由拿不到可靠底层连接信息时，由受保护的边缘层采集；不能从浏览器自填的头补出来。
- `observed_client_ip` 表示通过受控链路可靠观察到的访问源，可能是第三方代理的出口。
- `claimed_client_ip` 是第三方代理声明的原始客户地址。即使签名有效，也仅证明由该代理声明，不能据此宣称终端地址真实性已得到独立验证。
- `egress_ip`、上游连接地址归入转发尝试，独立于用户 IP 历史。未获得真实出站地址观测时显示未知，不能拿服务器私网地址推断公网出口。

信任条件：应用端口只接受指定边缘代理，配置可信代理 CIDR，入口清除客户端传入的内部身份头、签名头和地址头，再生成可信上下文。多层反代从最靠近服务的一端开始，逐跳验证并剔除可信代理，选择首个不可信节点作为可确认来源；不能固定取 XFF 最左项。若使用 CDN，只信任已认证的 CDN 连接来源。配置需要同时适配 IPv4、IPv6 和 Tunnel。

LFN 的 IP 记录、请求审计、注册/登录限流、业务限流、IP 访问控制和管理员审核统一使用这份上下文，不再各自解析转发头。基础依据见 [MDN 对转发头信任边界的说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Forwarded-For) 和 [Nginx Real IP 模块](https://nginx.org/en/docs/http/ngx_http_realip_module.html)。

**5. 对代理调用、上下游转接与中转的审核规则**

| 场景 | 可信归属 | 审核与执行方式 |
| --- | --- | --- |
| 站内工作台 | 已认证账号、会话、入口观测地址 | 按账号/会话限流，关联站内业务操作 |
| 用户直接调用 API | Key 归属账号、Key ID、入口观测地址 | 独立 Key 权限、配额、并发、IP 白名单 |
| 用户通过普通 VPN/正向代理调用 | 账号/Key、可观察到的代理出口 | 保留“出口地址”含义；无法可靠还原代理背后的地址；代理标签只作辅助信号 |
| 已授权合作代理转发给 LFN | `agent_id`、代理专用 Key、声明的下游客户标识、代理出口 | 按代理总额与其下游子额双重限流；声明单列；限制可转发能力 |
| 未授权转售/中转 | 可确认的 Key 主体、出口与业务行为证据 | 建立案件，按证据限流/临时封 Key/人工封禁；不能只凭机房 IP 或无 Referer 定罪 |
| LFN → NewAPI → Gateway → NovelAI | 可信内部身份上下文和逐跳调用记录 | 链路贯通、记录每次尝试、统一预算、核对实际用量 |
| LFN → 个人第三方服务 | LFN 账号、个人供应商配置及实际目标 | 同样通过平台准入；保留个人密钥模式与站点资金模式的独立能力策略 |
| 直接访问 NewAPI/Gateway | 直属服务身份或经准入的用户身份 | 私网/服务身份限制，或在该入口部署同等策略；禁止留有绕过 LFN 的公开后门 |

合作代理专用凭据与普通用户 Key 分开，至少设置：所有者、状态、到期时间、允许能力/模型、来源 IP 或网段、请求速率、并发、每日预算、是否允许下游客户、允许转接深度。

代理身份传播采用双方约定的认证协议：mTLS 或专属服务凭据；上下文带发行方、接收方、代理 ID、客户伪名、trace ID、时间戳、nonce、有效期和签名。校验接收方与重放；对请求内容签名时明确绑定当前一跳的请求摘要，协议转换后由该服务生成下一跳摘要，不能跨 JSON/multipart 转换盲目复用。

外部自填 `X-LFN-User-ID`、`X-Real-IP`、`X-Forwarded-For`、`traceparent` 等不能授予用户身份或封控豁免。原始关联 ID 如需保留，另存非可信字段。内部头只在受信服务之间使用，调用第三方上游时按最小头白名单清除。

代理深度与循环限制只约束可验证的合作链路；对隐藏代理层数无法可靠计数。默认允许的合作转接深度可设为 2，并通过请求链路防重放及路由检查阻止 LFN/NewAPI/Gateway 互指回环。

**6. 分级封控及明确作用范围**

每条限制必须包含：目标、能力范围、动作、原因码、证据、开始/结束时间、来源案件、策略版本、操作者及撤销状态。

| 目标 | 可执行的限制 |
| --- | --- |
| 账号 | 限制登录、生成、外部 API、邀请/领奖等单独能力，或停用账号 |
| API Key | 降低并发/速率、模型范围、预算；暂停或撤销该 Key |
| 会话 | 二次验证或撤销指定会话；必要时提升用户会话纪元 |
| 代理主体 | 暂停代理或指定下游客户，降低代理总预算，禁止进一步转接 |
| 精确 IP | 仅登录/API 等指定入口的挑战、限流或临时拒绝 |
| CIDR 网段 | 人工评估影响范围后实施短期措施，显示预计影响账号数 |
| 上游通道 | 因异常错误、成本或安全问题暂停通道，阻止自动回退绕过限制 |
| 关联账号集合 | 逐个保存被限制对象和证据；邀请链批量动作要求预览确定集合 |

推荐层级：正常 → 观察 → 限流 → 临时限制 → 人工封禁。风险分数用于排序和触发可逆措施；永久停用由人工确认并记录证据。

限制叠加采用“硬性账号/Key/能力封禁优先，其次所有仍有效的约束取交集”。IP 白名单只豁免它明确指定的 IP 规则，不能绕过账号停用、预算或 Key 撤销。IP 未知时不能当作已通过严格 IP 白名单；强制白名单的 API 应返回可解释的拒绝原因。

同出口、同网段或同邀请人不能单独触发永久封禁。对于公司、学校、家庭及运营商 NAT，优先处理有证据的账号/Key；批量网段封禁需要预览影响并设置到期时间。

完整账号封禁执行：先提交本地有效限制与动作日志，再撤销会话和本站 Key；同步自己管理的 NewAPI 用户/Key 状态，并同步合作代理/Gateway 的策略版本。同步采用可重试任务，后台分别显示“本地生效、上游待同步/已同步/失败”，周期对账。上游直连入口无法关停且不能同步时，明确标记“封控范围不完整”。禁止简单因本地操作成功就显示“全链路封禁完成”。

解封只撤销该动作创建的限制；多个案件、管理员手动停用及其他未到期限制继续生效。同步上游时保留此前状态及变更版本，避免误恢复原本就被其他原因禁用的账号。

新请求在转发前拒绝，排队任务在出队时再检查限制和预算。正在执行的付费生成标注执行状态；只有明确支持安全取消时才取消，不能承诺撤销已经发生的上游消耗。

**7. 风险规则与人工审核**

优先收集可解释的组合证据：

| 信号 | 建议处理 |
| --- | --- |
| 同账号重复使用同 IP | 正常更新统计，风险分不增加 |
| 同 IP 多账号 | 关联线索，结合时间、Key、行为及共享出口情况分析 |
| 新 IP/新地区登录 | 记录；结合会话状态决定提醒或二次验证；位置仅为网络归属 |
| 同 Key 短期跨多个来源并发使用 | 检查是否为合法服务部署或代理，必要时临时限制 Key |
| 多账号协同绕过并发/额度 | 将有因果关联的请求、配额和凭据证据放入同一案件 |
| 大量认证失败、撤销 Key 继续调用 | 登录防护或精确 Key/IP 短期限流，避免攻击者触发受害账号永久锁定 |
| 持续规则化调用、无页面行为、机房 IP | 弱信号；合法 API 客户端同样可能具备，不单独认定中转 |
| 高频转发叠加多客户声明、跨主体配额转移等 | 核对代理授权，必要时暂停代理能力并人工复核 |
| 重复提示词 | 考虑公开模板、热门示例与同一作品修改，不能单独认定滥用 |
| 401/403/429/5xx 或大量重试 | 区分来源；上游故障和 Gateway 排队不应自动算作用户恶意 |
| 高成本、异常放大参数、循环转发 | 入站参数与预算限制；拦截确定的无效请求或回环 |

规则事件按 `(主体, rule_id, 时间窗口, 证据集合)` 去重。同一事实反复读取或同一代理链多次上报不重复加分；持续行为可以更新次数。设置每类信号上限和随时间衰减，误报豁免有适用条件、到期时间与复核记录。

作为待校准初值，可沿用当前 40/60/80 分档：40 进入观察，60 优先审核，80 且具备至少两类独立证据时触发短期限制。自动限制初始 15 分钟，升级需持续的新证据；永封与大范围限制人工审核。初值应先在影子模式验证，不能当作已经有效的生产阈值。

案件页面一次展示：主体及 Key、去重后的 IP、可信度、同 IP 关联账号、代理/上游链路、请求与实际成本、规则版本和证据时间线。操作为观察、要求验证、限流、临时限制、封禁、误报、解封、处理申诉；记录前后状态和实际执行结果。

**8. 上下游审计、成本与幂等**

在可信入口生成 `trace_id`，内部各跳有独立 `span_id`；同一业务操作另有稳定 `operation_id`。外部 ID 不覆盖内部主键。NewAPI/Gateway 若不能传播，则用受控适配器或持久映射补齐，并标记链路断点。

每次上游尝试至少记录：所属业务操作、服务/代理、通道及凭据 ID、模型/操作、时间、状态、排队/执行耗时、重试原因、实际返回样本数、计费来源、上游用量与其可信度。请求正文默认保存必要参数摘要；密码、Cookie、完整 Key、服务签名和图片二进制不进入审计。

区分业务操作数、上游尝试数、实际生成样本数和计费次数。例如一次生成因重试产生三次尝试，只算一个业务操作，但三次尝试及已确认成本都保留。客户端重试只有携带有效幂等键才可复用操作；相同提示词或相同 IP 不能作为重复业务操作的判据。

幂等键按账号/Key 和端点作用域保存，绑定规范请求摘要；同键不同参数拒绝。扣费/退款账本使用唯一结算键，处理跨进程重复请求。遇到上游是否已执行不明的超时，先标记待确认，不自动无界重试；无法获得上游幂等支持时，不能声称全链路恰好执行一次。

出站转发按已登记协议和目标构建最小头集合。用户可配置第三方地址时延续已有公网地址校验、DNS 解析后固定连接目标、响应大小限制和禁止不安全重定向；可信私网上游作为单独配置的服务目标，不被用户配置引用。网关环境代理属于另一条受控出站路径，也应登记和审计。依据见 [OWASP SSRF 防护说明](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

关联 ID 和敏感字段处理参考 [OWASP 日志说明](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)；这里列出的表结构、策略及阈值均为针对 LFN 的设计建议。

**9. 执行架构、异常处理和保存期限**

公共准入顺序：入口请求上下文 → 基础限流与身份认证 → 账号/Key/能力/IP 限制 → 行为规则与预算 → 创建业务操作 → 资金预留 → 入队 → 出队复查 → 上游尝试 → 确认产出与结算 → 审计归档。

覆盖清单包括站内生成/编辑/放大、个人服务商、OpenAI `/v1/*`、NAI `/ai/*`、透明回退；登录、注册、兑换、奖励等使用相应能力策略。UI 隐藏按钮不构成准入保护，所有服务端入口都需要校验。各跳权限验证的原则见 [OWASP REST 安全说明](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)。

PostgreSQL 保存主体、IP 关系、案件、限制、操作日志与结算关联；Redis 使用原子操作维护共享滑动窗口、预算预留与并发租约。单进程 JSON 可作为迁移来源，不能继续承担多副本的唯一性和一致性保证。封控动作与待同步任务在同一数据库事务提交。

故障策略明确区分：

- 硬性封禁、强制 IP 白名单和资金授权无法验证时，受保护的生成/API 请求返回暂时不可用，不继续消耗上游；读取帮助、申诉等保留必要通道。
- 地理库或代理标签查询失败时显示未知，不据此封禁用户。
- 非关键分析异步排队；关键动作日志与支付状态持久化失败时不报告成功。
- 缓存和同步任务具有版本、最大滞后监控与重试；旧缓存不能无限期放行已封禁主体。

建议初始期限：可解密 IP 及账号关联保留 30 天；详细请求审计 30 天；案件与管理操作 180 天。均为产品建议，需配置并公开；案件需要延期时限定对象和用途。过期清理同步删除密文、索引、关联及缓存，并说明备份的最终过期窗口。保留日统计时应明确哪些统计仍能关联个人。页面显示“保留期内 IP”，不再笼统称“全部历史 IP”。

**10. 实施顺序与验收**

| 阶段 | 交付内容 | 验收门槛 |
| --- | --- | --- |
| P0：地址准确性 | 统一 IP 上下文、规范化、账号/IP 唯一聚合、登录/请求分开统计、旧数据合并、入口审计 | 同 IP 不增行；伪造地址头无效；同一事件不重复计数 |
| P1：范围审核 | 时间/IP/CIDR/来源/可信度过滤、权限、范围内统计、分页和导出 | 权限在统计/查询前生效；完整地址默认不返回；窗口计数准确 |
| P2：封控闭环 | 公共准入、能力/Key/代理/IP 限制、到期、撤销、上游同步、排队复查 | 各协议和回退路径拒绝同一被限制主体；同步失败可见并可恢复 |
| P3：代理与成本 | 代理主体登记、签名上下文、链路关联、上下游尝试、幂等结算、反回环 | 能追踪并解释一次调用各跳与成本；隐藏链路显示未知 |
| P4：策略校准 | 影子模式、误报复核、按群组小流量执行、指标监控 | 评估误报/申诉率、限制延迟、链路完整率、重复 IP 率与重复结算率后逐步扩大 |

已有封禁可绕过的入口盘点与修复属于 P0，不等待 P2 才处理；P2 扩充的是封控能力和同步闭环。

必须覆盖的验收用例：

1. 同用户同 IP 登录 100 次，IP 列表 1 行；真实成功登录数 100，Cookie 读取不增加登录数。
2. A → B → A 仅 2 行；同地址的 IPv6 不同文本形式、IPv4 映射形式按规则归一。
3. 多进程并发写同一账号/IP 仍 1 行；重复投递同一事件不重复累加。
4. 两用户共用同 IP，各自 1 条关系；全局 IP 能看到两个账号且各自次数正确。
5. 同 IP 的两个会话可以独立查看/撤销，IP 聚合不删除安全事件或会话。
6. 注入 XFF、X-Real-IP、内部用户 ID 或关联 ID 不能冒名、绕过限流或污染可信证据；应用直连入口受阻。
7. 登录、站内调用、NewAPI 和 Gateway 上报同一次业务事件时，业务计数不重复；无关联 ID 的旧数据明确标识不确定。
8. CIDR/地址段/日期过滤、窗口内次数、分页总数及导出一致；跨组用户和案件不能通过数量接口泄露。
9. 已封禁账号换 IP、换端点、走原生协议、个人供应商或 NewAPI 回退，仍服从对应的能力限制；支持的直连路径同步限制生效。
10. IP 白名单不能覆盖账号封禁；IP 未知不能通过强制白名单；临时限制按期解除且不撤销其他案件限制。
11. 批量邀请链/网段操作预览实际对象，关系变化要求重新预览；共享出口不自动造成永久连坐。
12. 合作代理签名伪造、重放、错误接收方或过期被拒；签名声明的客户地址仍显示其来源可信等级。
13. 上游同步失败、Redis 故障、进程重启、队列等待时封禁、上游超时和部分出图均有明确状态与恢复路径。
14. 代理链三次重试为一笔业务、三条尝试；相同幂等键不重复扣费，同键改参数被拒，未确认执行不盲目重复生成。
15. 密钥轮换不新增重复 IP；过期清理覆盖查询索引和缓存；有限保留期在界面可见。

迁移先备份、只读回填和核对，保留原记录与稳定映射；不能在没有证据的情况下把旧会话活动推算为成功登录。双读核对后切换新读路径，再逐步停用旧写入。本文只交付设计，不包含生产迁移、封禁或付费上游调用。
