## 3. 总体设计与默认功能开关

采用：**少量实时计数 + 明确规则 + 低频增量汇总 + 异常后按需检查 + 有期限的处置**。

| 功能 | 建议默认 | 说明 |
| --- | --- | --- |
| 免费额度总量 | 保持当前 | 调整调用节奏不等于扣减每日总额度 |
| 鉴权、权限、余额与有效封控 | 始终执行 | 不作为可绕过安全不变量的业务开关 |
| 每日免费授权、同时一个有效出口 | 开启 | 每账号每天一份记录，有限换绑 |
| 严格全天不允许换IP | 关闭 | 提供严格档位，但默认保留正常换网路径 |
| 账号级速率/并发/队列限制 | 开启 | 账号总约束不能通过换Key/IP/端点重置 |
| IP异常、设备异常、作息异常 | 开启观察 | 不单项认定滥用 |
| HMAC-SHA256精确重复检测 | 开启观察 | 单账号与跨账号短索引，均设容量上限 |
| 仅凭重复Prompt自动封禁 | 关闭 | 需要独立证据及对应规则 |
| 实际消耗与预留统计 | 开启 | 不同单位分开；账本仍保证原子性 |
| 内容明确拒绝计数与持续尝试 | 有受信来源才启用 | 未接入/无通过分母时显示覆盖不足 |
| 七级风险与规则分值 | 开启 | 弱信号高分也不能自动变成确认事实 |
| 随机签名设备Cookie | 开启轻量版 | 不增加硬件指纹与独立请求 |
| 地区/代理/VPN标签 | 缓存观察开启 | 外部查询默认关闭，缺失是unknown |
| 每次免费生成的人机验证 | 关闭 | 不新增每次等待 |
| 异常时人机验证、MFA/持有证明 | 预留关闭 | 未实现的验证不能充当已可用恢复条件 |
| 语义相似度、多模态新增审核、全量图谱 | 关闭 | 按需扩展，不为凑开关实现重能力 |
| 合法高频申请与有限自动批准 | 开启 | 批准具体速率/期限，不免除资金与内容规则 |
| 端口扫描、猎奇图替换、暗改结果 | 不实现 | 不能证明中转，并会破坏交付 |
| 手机首页布局修复 | 批准后默认启用 | 通用布局正确性不是某型号专属惩罚策略 |
| 声明采用LFN阶梯的API严格一致性 | 开启 | 无法执行时明确拒绝/不可用，不静默换收费政策 |

## 4. 配置系统与后台规范

全部业务配置使用统一、严格校验、版本化Schema；后台操作必须真正驱动后端。每项提供稳定字段名、中文名、类型、默认值、单位、允许范围、依赖、作用域、实际生效值、性能/误报影响和就绪状态。

- 生效模式：`disabled`、`observe`、`enforce`；确定性鉴权、余额、撤销凭据和已生效限制不随观察模式旁路。
- 全局默认→用户组/套餐→账号类型→入口/能力→限时个体例外，解析顺序固定；界面展示最终值和覆盖来源。
- 支持草稿、校验、差异、发布、版本、灰度、回滚、恢复默认、脱敏导入导出、修改理由及审计。
- 乐观并发控制防止管理员互相覆盖；拒绝未知字段、非有限数值、不合法单位、阈值倒置和超容量规则。
- 策略缓存启动加载/发布更新；不逐请求扫描配置文件。多进程使用可靠版本失效或共享准入状态。
- 关闭规则不自动解除其既有处置，更不能覆盖其他案件；另设有权限的“解除指定处置”操作。
- 扩展供应商凭据仅在服务端保护、掩码展示；不能允许SSRF、任意脚本/SQL、用户自行指定可信标签。
- 审计不可由普通配置操作抹除。涉及完整IP、跨账号关联、密钥管理与批量封控分别授权。

下面给出配置字段合同与初始值。正式Schema必须为每项落实类型/范围；“沿用现有套餐值/必填”意味着实施时读取并展示现值，**不能暗自给所有用户设置一个新的统一限额**。

## 5. 每日授权、设备与地址配置

| 配置组 | 字段与初值 | 校验/执行要求 |
| --- | --- | --- |
| `grant` | enabled=true；autoIssue=true；timezone=Asia/Shanghai；dayMode=calendar；maxActiveExits=1；strictNoRebind=false | 用户+自然日唯一，首次并发原子建立；不以重签重发额度 |
| `grant.rebind` | enabled=true；maxPerDay=2；minIntervalSeconds=900；verification=existing-reauth；oldGrantInvalidation=immediate | 次数0–20，间隔0–86400秒；未就绪验证方式不可选；换绑不重置计费/处罚 |
| `grant.scope` | 免费能力开启；付费/API独立权限；账号受限后禁止换绑绕过；例外必须有到期 | 枚举能力而非只控制按钮；API不能拿浏览器免费授权当上游Key |
| `grant.token` | 不可预测临时凭据；有限有效期；可撤销版本；cookie/header载体按客户端选择 | 绑定账号、授权ID、出口标识、时效、版本和用途，不包含上游凭据；不替代身份认证 |
| `ip` | trustedResolver=统一入口；binding=exact；IPv4/IPv6规范化；rawReveal默认关闭 | 未受信请求头不能改变授权；前缀绑定仅显式配置并提示保护减弱 |
| `device` | enabled=true；mode=signed-random-cookie；valueMaxBytes=100；cookieTtlDays=30；knownRelationRefreshSeconds=3600 | 默认无指纹SDK；HttpOnly、SameSite，HTTPS下Secure；Cookie名/期限可配 |
| `device.capacity` | devicesPerAccount=8；accountsPerDevice=16；relationRetentionDays=7 | 上限均有明确范围；新关系/切换即时更新；满额显示“至少达到上限”，不伪精确 |
| `device.rules` | 同设备24小时≥3账号观察，≥5账号且存在可靠协同证据才处理；设备切换1小时≥8观察 | 窗口、阈值、并发设备数、分值、证据组合和动作独立可配；UA/IP变化不等于设备变化 |

每日授权流程：原有鉴权→当天授权加载/创建→出口匹配→已有限制/预算→生成。同出口恢复不增加额度；出口变化进入重新确认；新绑定生效后旧绑定失效；日切不解除仍有效的封控。无设备Cookie显示未知，不记违规；API客户端无需设备SDK。

每天一份授权只限制可用出口轮换，**固定出口代发仍可能存在**，因此速率、账号预算及行为证据仍不可少。

## 6. 七类特征与可配置指标

### 6.1 F：速率、并发与队列

配置 `rate.enabled/mode`、账号持续速率、时间单位、突发容量、样本速率、Key子限额、免费/付费并发、模型/操作覆盖、最大排队数、等待秒数、IP短窗保护、每日IP观察量、Retry-After方式、重复拒绝摘要间隔。默认沿用现有批准的套餐值；免费并发建议起点1，由审核/容量校准后确定。

账号限制独立于“账号+IP”组合。多图、超分等按样本与成本考虑；请求超正常合同速率本身加0分，直接执行资源限制。固定桶只能声明桶精度，不能冒充严格滑窗；资金硬上限仍由原子账本预留控制。

### 6.2 B：提示词与行为

| 配置项 | 初值/范围要求 |
| --- | --- |
| `prompt.enabled/mode/algorithm` | true / observe / HMAC-SHA256；普通SHA256作为显式可选模式，标明离线猜测风险 |
| `prompt.normalization` | Unicode=NFKC、trim=true、collapseWhitespace=true、caseFold=false；保留词序/数字/权重；版本化 |
| `prompt.inputs` | 用户正向文本；负向文本默认不计；排除受信的系统公共注入模板；原文/预览默认不新增留存 |
| `prompt.acceptedLength` | 沿用业务合法长度；摘要覆盖完整已接受文本，禁止只截断前缀造成假重复 |
| `prompt.sameUser` | 最近16个；最少10样本；重复比例80%；窗口、连续重复数、分值、贡献上限及动作可配 |
| `prompt.crossAccount` | 10分钟、≥3账号、≥5调用；索引2000摘要，每摘要最多8关联账号；饱和状态单列 |
| `prompt.version/retention` | 全站同版本密钥保证可比较；密钥轮换、保留期、过期及版本迁移明确配置 |
| `behavior` | observe；每天6时段；7有效日基线；近期≥30次、历史≥100次；15分钟增量更新 |
| `behavior.thresholds` | 分布偏差、调用间隔、持续活跃时长、时区口径、批量大小均配置；不足样本显示unknown/insufficient |

重复摘要只能证明规范化文本相同，不能证明中转、多账号属于同人或语义近似。公开模板、改稿、正常自动化只观察；跨账号摘要索引不扩展成全量历史聚类。

### 6.3 Q：额度消耗

配置 `quota.enabled/mode/windowSeconds=300`、分单位/套餐绝对门槛、`accelerationRatio=5`、最小基线、资金来源范围、赠额快速使用比例、消费/预留小计、`baselineUpdateSeconds=900`、`minActiveDays=7`、`minSettlements=30`、`baselineAdmissionDelayHours=24`、异常样本隔离、组合证据要求和暂停时长。

绝对费用门槛由现行定价与合法用户样本确定，未配置不得启用倍率处罚。AFF、图包、赠额与Anlas分开记录或按明确版本换算，不能混加。正常付费大批创作不等于套利。退款修正原操作、部分产出按原报价分样本结算；执行不明先对账。

### 6.4 C/E：内容、失败分类与持续尝试

受信审核来源、结构化错误码、内容类别/严重程度、最低置信度、结果覆盖、频次/比例窗口、最低样本、反馈后新操作数、内部重试去重、退避期限/违背阈值、证据保留及升级档位分别可配。

结果至少区分：明确内容拒绝、明确通过、待复核、审核不可用、风控拒绝、普通限流、参数错误、余额不足、鉴权失败、上游超时/故障、用户取消、成功/部分成功。403/429/5xx及自由文本不能直接当违规。

- 初值：10分钟≥5次独立明确违规，反馈后≥3次新违规→相关能力暂停30分钟。
- 初值：30分钟有效已审操作≥20、明确拒绝比例≥40%，反馈后≥3次新违规→相关能力暂停并复核，最长24小时。
- 初值：明确冷却期限前，已鉴权新请求每分钟≥10次、连续2分钟→相关Key/会话一次固定5分钟保护。
- 分母只能包含明确通过+明确拒绝的独立已审操作；只有拒绝结果而没有有效通过覆盖时不能伪造比例。
- `feedbackSentAt`仅代表服务端已发反馈；之前已在途的并发不计“无视反馈”。内部重试和同幂等操作不重复处罚，真实到达仍占入口速率。
- 幂等键绑定主体与正文摘要，同键换正文拒绝；新操作重复同一Prompt仍是新调用。

### 6.5 N：地区、代理与VPN

配置地区/ASN/来源名单、依据/版本/有效期；VPN/Proxy/Tor/Hosting各自开关、来源、置信度、TTL和分值。`unknown`、过期、查询失败分别展示。

默认已有缓存观察开启，外部供应商关闭；可选查询只针对已有异常的新来源。初值：本地缓存24小时，外部同IP24小时一次、失败负缓存1小时、全局5次/分钟、并发1、超时1秒、队列100。上述值可配并有总预算。

查询合并、队列满跳过可选查询，不阻塞普通生成。地区/VPN单项不永封，确认恶意来源的入口保护也不能自动认定出口下全部账号违规。

### 7.3 去重、上限与衰减

- 同事件可展示多个理由，但同一证据族不重复满额计分；Prompt+IP等弱关联也不冒充两条独立强事实。
- 网络标签初始合计上限10；行为20、设备20、额度40、内容/持续违规共享100、确认规避/套利100。各族上限可配置，默认总分最多200。
- 维护有界活动证据贡献，不逐请求扫描全部历史；限制每账号活动证据数及规则数，满额按规则合并，明确饱和状态。
- 一般观察证据默认24小时半衰期，支持关闭/线性/指数衰减；按类型可设置有效期。明确违规案件追溯窗口初值7天；分数衰减不删除案件事实。
- 后台重跑、事件重放、重复拒绝、政策发布不能再次加分。误报结案移除对应贡献，保留审计。
- 人工调分、确认案件、解除限制、撤销Key是不同权限和操作，不能相互隐式替代。
- 旧累计分不直接按新等级触发自动处罚；迁移时保留历史和人工封禁，从可用窗口事实重算，无法重算显示证据不足。

## 8. 处置、恢复、信任等级与合法高频

动作类型至少包括：记录、观察、降并发、限速、重新登录/授权确认、暂停免费能力、暂停指定生成能力、撤销每日授权、撤销相关会话/Key、暂缓待发奖励、人工复核、管理员封禁/解除。

每个动作配置主体、能力、时长、最大时长、证据条件、错误码/文案、是否影响付费与个人供应商、合并优先级、恢复方式、复核权限与通知方式。无可用验证通道时不能把“去完成不存在的验证”当恢复条件。

处置实例固定 `startsAt/expiresAt/maxExpiresAt`。重复拒绝不刷新到期；到期有限恢复；新的独立确认违规才升级。初始递进为7天内独立案件30分钟→2小时→24小时，档位/次数/窗口均可配置。达到高档转复核，不自动永封。

账号信任等级与风险等级分开：新账号、普通、稳定可信、已授权API/合作主体、受限/待复核。升级条件包括账号年龄、验证状态、正常活跃日、记录覆盖、最近确认案件、用途授权，逐项可配置；充值/账号老不能自动消除违规。

高频申请包含用途、模型、期望速率/并发、期限与作用域；可配置自动批准条件、最大提升幅度、有效期、人工审核、撤销与到期恢复。默认只提升调用节奏，不增加免费总额度；白名单不能绕鉴权、余额、内容硬规则和审计。

邀请链或设备关系不自动连坐。批量操作必须先预览真实关联证据和影响范围，再按权限执行，记录每个账号结果；解除只撤销指定实例。

## 9. API 阶梯计费统一修复

### 9.1 目标与策略选择

对**计费模式明确为LFN每日阶梯**的模型/能力，站内、OpenAI兼容、NAI原生及流式入口必须共用账号、系列、日期、报价、预留、扣款和退款。换Key不重置张数，换端点/回退不换低价路径。

为每个模型/能力显式配置 `billingMode`：

- `lfn_daily_tiered`：采用LFN每日阶梯，默认禁止静默NewAPI余额回退。
- `fixed`：显式固定单价，含0价；后台明确“固定价优先/不采用每日阶梯”，不能显示为阶梯已生效。
- `newapi`：仅对管理员明确登记的其他计费产品/能力使用，界面及API响应标明来源，不声称LFN每日阶梯。

保留已有合法固定价和独立产品的业务含义，迁移时展示旧优先级并显式映射，不能无声改价。不得让请求者临时选择`newapi`来绕过管理员为其模型/身份指定的阶梯。

### 9.2 回退与单次收费

- 无法归属用户时，不执行需要用户累计的LFN阶梯；区分身份无效与账号服务不可用，明确拒绝/503，不透明放行。
- 本地余额不足时，返回明确余额状态，不自动改用另一钱包收费。用户如选择另一已授权计费产品，必须显示/确认其政策；确认收费不等于获准绕过原阶梯。
- 上游回退只替换执行通道，若仍声明LFN阶梯，保留原报价和预留，不重复计数/扣款。
- 没有合法执行通道时明确失败并释放应释放预留；不能为完成请求悄悄换价。
- 若未来确需NewAPI执行而仍由LFN计费，必须使用受控服务身份，验证不会再次扣用户NewAPI余额；未经对账不得开启。
- 账户服务、阶梯状态、资金状态无法确认时停止相应付费调用；不能把可用性故障当用户违规。

### 9.3 详细计费配置

| 配置组 | 必备项 |
| --- | --- |
| `billing.scope` | 各模型/能力模式、站内/API/原生/流式统一范围、系列归属、参与累计的操作、固定价覆盖关系 |
| `billing.day` | Asia/Shanghai自然日；跨日请求归属按受理日冻结；过期预留回收、执行不明对账策略 |
| `billing.tiers` | 每系列阶梯数量、每档起始张数、基础价/附加价、Anlas倍率、总倍率、币种/单位和版本 |

API返回保留兼容格式；通过允许暴露的响应头及受权限控制的查询提供支付来源、请求ID、必要的费用/政策版本说明。单张、多张、流式、ZIP/MsgPack均核对最终产出，不能把“上游200”直接当全样本成功。

## 10. 手机生图首页修复规格

### 10.1 根因调查顺序

以下是待验证假设，不是已确认结论：

1. 无图→预览/自然尺寸到达时，图片、按钮组、Grid/Flex子项的固有最小宽度或回退像素尺寸撑开祖先。
2. 键盘、浏览器地址栏、页面缩放导致visual viewport与layout viewport不同，固定弹层或坐标计算沿用过期值。
3. 横向进入动画及结束后保留的transform改变固定定位包含块，或动画/抽屉切换造成暂时越界后未恢复。
4. 大图/抽屉关闭、生成异常或卸载时body滚动锁、padding补偿、pointer capture、touch-action或遮罩状态未清理。
5. 触摸/滚动事件preventDefault范围过大，或隐藏遮罩截获触摸，使错位后无法拖回。
6. ResizeObserver读写反馈、首帧测量为0、隐藏→显示或横竖屏时测量失效，导致循环或错误宽高残留。

先采集证据再改动。重点检查：`studio.tsx`、`mobile-studio-launcher.tsx/.css`、`replica-media.tsx/.css`、`globals.css`、`layout.tsx`及实际参与的抽屉/大图/菜单组件；不要先重写整个工作台。

### 10.2 开发诊断与复现步骤

仅在开发/显式调试时，按“初始→请求→预览→最终图片加载→弹层/键盘关闭”记录：

- `innerWidth/innerHeight`、根clientWidth/scrollWidth、body尺寸、scrollX/Y；
- `visualViewport.width/height/offsetLeft/offsetTop/scale`、DPR与方向；
- 首页根、结果容器、图卡、导航、生成按钮、抽屉的bounding rect、计算宽高、overflow/transform/touch-action；
- activeElement、遮罩和滚动锁状态、图片自然尺寸；
- 是否发生ResizeObserver循环或pointercancel/lostpointercapture未清理。

不采集Prompt原文、图片内容或身份凭据，不增加生产常驻轮询/全DOM扫描。仅当明确需要上报时另行设计脱敏、采样、容量和权限。

复现流程：进入生图第一页→输入Prompt→打开/关闭输入键盘和参数抽屉→用本地模拟上游返回图片→观察横向偏移与触摸→继续生成→查看/关闭大图→切换历史后回到生成→横竖屏及前后台切换。分别保留冷缓存/已缓存和首张/连续生成结果。

### 10.3 修复原则与配置边界

- 明确每层宽度和滚动所有者；必要处使用`min-width:0`、受父容器约束的图片尺寸与稳定布局，而非让图片自然宽度撑开页面。
- 区分CSS像素、物理分辨率、页面缩放与视觉视口，不能按“2800px页面宽度”修复。
- 动画结束状态、固定定位/Portal、滚动锁要在正常/异常/取消/卸载路径可靠恢复；图片交互的pointer capture需正确释放。
- 只在相关组件和必要事件上监听，读写合批、使用稳定测量、卸载清理；不对每帧持续调用setState或scrollTo。
- 保留正常纵向滚动、浏览器缩放、允许的图片缩放/拖动、输入焦点与无障碍交互。
- 禁止将“刷新页面”“全局负margin补偿”“全页touch-action:none”“禁止用户缩放”“每帧强制scrollTo(0,0)”作为修复。
- 根容器防横向越界可以作为明确布局的一部分，但不能只靠隐藏溢出来掩盖不可达控件或未清理的位移状态。
- 不按vivo/Edge UA硬编码偏移量；模拟通过不能宣称真机已修复。

通用布局与清理正确性默认启用，不做用户需要手动打开的“修复开关”。如果确需兼容分支，配置包含作用范围、启用/灰度、诊断、撤销与弃用条件；诊断默认关闭，动画可遵循prefers-reduced-motion。业务布局算法不是任意可调CSS脚本。

### 10.4 验收标准

1. 正常比例、键盘关闭、未缩放的稳定状态下，根scrollWidth不超过clientWidth 1 CSS px；关键控件在视口内且可触达，不是被裁掉。
2. 生成前后根/导航/操作区无不可恢复横向偏移；稳定状态scrollX约0。缩放或键盘打开时按实际视觉视口解释，不粗暴强制归零。
3. 首张、连续至少10次模拟生成、不同结果尺寸和流式预览结束后，均可继续输入/提交，不需刷新。
4. 大图、参数抽屉、菜单、键盘关闭或手势取消后，主界面正常滚动和触摸恢复；图片交互仅在其区域生效。
5. portrait/landscape、地址栏伸缩、前后台切换、窄屏、长文字、多图、失败/取消/重试均无残留遮罩或位移。
6. 无新增常驻轮询、ResizeObserver循环、监听器泄漏或明显长任务；桌面工作台及其他皮肤不退化。

| 初始容量新增风控状态内存 | 目标≤24MiB | 含对象、索引、队列；需实测，不是字符串裸大小 |
| 多进程准入 | 目标一次有界原子共享操作 | 不把pipeline当原子，不声称与账本跨存储天然事务 |

单进程复用已有持久存储，内存仅保存有界短窗状态。每日授权、有效限制、资金、必要违规证据必须持久；有效限制恢复完前不接付费请求。短窗观察重启丢失可作为明确折中，不能影响唯一资金约束；冷启动用已批准保守限额。

缓存满先分批回收过期项、停可选观察；必要准入无法安全计数时短暂429/503，不记用户违规。不淘汰有效限制换取放行。普通诊断可合并/降采样，资金、权限、限制及必要证据不只放易失队列；必要证据写入失败按受影响能力退化，不冒充成功保存。

若实际多进程/多副本，账号预算/速率、授权唯一性与必要违规计数必须共享原子执行；只有内存锁时明确不支持全局正确性。外部服务不可用不增加用户恶意分。任务幂等与断点、租约/预留超时、重放去重均有配置和测试。
