# LFN 生成调用风控专项规格

日期：2026-10-17。状态：需求与实施规格，尚未接入运行代码、部署或对真实账号执行限制。

性能折中更新：当前默认落地方向改为[轻量风控方案](./LFN-LIGHTWEIGHT-RISK-PLAN-20261017.md)，以有界计数、固定规则和低频汇总实现。本文较重的实时评分、语义分析和图谱能力保留为扩展需求。

本篇把额度滥用、行为异常、设备关联、内容风险、调用频率、反复触碰边界、网络与地区七类需求展开到指标和处置。它补充[账号安全与反中转方案 V2](./LFN-ACCOUNT-SECURITY-RISK-V2-20261017.md)，不替代其中的认证、凭据隔离、注册及反中转要求。本文分数、次数和时间都是待历史回放校准的候选参数。

## 1. 核心决策方式

采用“硬约束 + 七维动态评分 + 独立场景规则 + 有期限的处置”。

- 身份、权限、已撤销凭据、有效封控、余额、预算、并发、速率等硬约束先检查；高风险内容当次拒绝不等待累计次数。
- 七维评分描述当前窗口风险，用于排序和组合规则；关联证据不直接等于违规事实。
- 明确内容违规后的持续尝试、已确认凭据泄露、硬预算耗尽分别独立处置，不能被其他低分冲淡。
- 暂停的主体、能力、原因、起止时间和恢复条件单独持久化；不能把“案件分达到 100”当作永久封控状态。

所有入口共享账号级约束，再叠加 Key、会话、设备、已确认关联主体、模型/操作、上游通道与全站约束。换 Key、端点或供应商回退不能重置同一账号的限制。

## 2. 当前代码能提供什么

以下是当前工作区静态观察，尚未核验生产部署、流量或上游规则。

| 能力 | 已有基础 | 本次要求的缺口 |
| --- | --- | --- |
| 频率与量 | `risk-control.ts` 支持短窗请求数、5 小时/7 天调用量和管理员配置 | 缺秒级突发、多种成本单位和多实例共享原子限制 |
| 提示词重复 | 有规范化 HMAC、形状摘要、跨账号聚类 | 缺单账号重复占比、基线偏差和可靠近似聚类；相同请求重复评估也需幂等 |
| 风险状态 | 案件、信号、人工封禁与审计 | 当前分数主要累加；重复提示词命中会给关联案件继续加分，需改为有期限证据、去重和重算 |
| 消耗 | 审计含部分 AFF/Anlas 字段；结算含扣款、退款与产出 | 口径覆盖不完整；不能把调用榜估算 Anlas 当作真实用户扣费，也不能直接混加不同单位 |
| 请求结果 | 有状态码、错误、时长和产出 | 缺版本化内容审核、明确错误分类、响应反馈时间及重试关联 |
| 设备 | 部分请求有 UA、会话信息 | 未见可靠的第一方设备登记与设备—账号事件链；UA 不等于设备指纹 |
| 网络 | 有可信代理开关、IP 证据、离线归属地和可选外部查询字段 | 离线归属地不提供 VPN 信誉；需独立来源、时效、覆盖率及准入接入 |

还要统一地址可信边界：`risk-ip.ts` 优先受信入口覆盖的 `X-Real-IP`，现有审计地址散列和通用限流键的取值路径与之不同。新规则必须统一调用一个可信地址解析器，未受信的请求头不得用于地区加分或主体关联。

不能依靠现有最多 5,000 条审计、20,000 条风险事件或 100,000 条使用事件的截断文件保证 28 天基线完整。新特征使用持久事件及按小时汇总，显式记录覆盖范围；文件锁只覆盖单进程，多副本必须迁移共享原子存储。

## 3. 统一事件与结果口径

安全事件最少包含：

| 字段组 | 要求 |
| --- | --- |
| 身份 | 内部 `user_id`、`key_id`/`session_id`、可用的 `device_id_hmac`、认证保障等级；不保存原始 Key/Cookie |
| 关联 | 服务端 `event_id`、`request_id`、`operation_id`、`attempt_id`、可选幂等键摘要、案件/处置 ID |
| 时间 | 服务端受理、决策、开始上游、完成、反馈发送时间；客户端时间单列为自报 |
| 操作 | 入口、模型、能力、样本数、预计成本、实际成本、成本单位、资金来源和结算状态 |
| 结果 | 业务结果类别、审核类别/来源/版本/置信度、上游结构化错误码、产出数量 |
| 来源 | 可信地址角色、IP HMAC、网络快照与情报版本、设备证据级别 |
| 决策 | 命中规则、特征值/样本量/窗口、策略版本、处置范围、反馈码及实际执行结果 |

`feedback_sent_at` 表示服务端发出明确拒绝或冷却反馈，不能证明用户已阅读。只有服务端受理时间晚于该时间的独立后续尝试，才进入“反馈后继续尝试”口径；之前已在途的并发请求不算。

结果必须至少区分：

| 类别 | 是否计内容违规 | 后续重试如何处理 |
| --- | --- | --- |
| `content_denied` | 仅明确、受信且符合平台规则的拒绝计入 | 关联拒绝类别、操作和后续独立尝试 |
| `content_review` / `moderation_unavailable` | 否 | 待复核或按必审能力暂停，不能给账号记违规 |
| `risk_denied` | 否 | 可计已反馈后的边界尝试，不回流为新的内容命中 |
| `rate_limited` | 否 | 超过反馈截止时间再试是正常行为；截止前密集重试才观察退避违背 |
| `invalid_request` / `insufficient_credit` | 否 | 多次独立无效请求可短时保护接口，不产生内容处罚 |
| `auth_failed` | 否 | 来源防护；未鉴权请求不能给其声称的受害账号加分 |
| `upstream_timeout` / `upstream_error` / `client_cancelled` | 否 | 平台退避、熔断或取消；不增加账号违规分 |
| `succeeded` / `partial_success` | 否 | 按实际产出和最终结算记账 |

HTTP 403、429、5xx 和自由文本错误不能直接映射为内容违规。上游只给笼统失败时，类别为未知或上游故障。审核分母只包含得到有效审核结论的独立操作，未接入、超时和待复核操作不进入分母。

计数分成两条：真实到达请求均计入入口资源速率；内容处罚按独立、已审核的业务操作计算。服务端内部重试和相同有效幂等键的同一操作只计一次违规。幂等键按已鉴权主体绑定正文摘要；同键换内容拒绝，重复响应不再次访问上游。同样提示词换新操作执行是新的调用，不能自动当网络重试忽略。

## 4. 七类指标

默认窗口为 10 秒、1 分钟、5 分钟、1 小时、24 小时、7 天，个人基线最长 28 天。窗口使用服务端时间，并排除未来时间事件。评分证据带 `available`、`insufficient`、`stale` 或 `unknown`、覆盖率、样本量及置信度。

### Q：额度滥用

额度指实际资源消耗，不只看余额减少。分别维护 AFF、图包单位、上游 Anlas、赠额和其他资金来源，禁止混加；有经版本化定价换算时可另建统一成本视图。

- `settled_spend_5m`：独立已结算操作的最终净扣款之和；按原操作受理窗口归因。退款修订原操作消耗，不在退款发生窗口制造负消费。
- `reserved_spend_5m`：仍有效的原子资金预留，单列；不能等完成扣款后才控制在途消耗。
- `spend_rate = settled_spend_5m / 5`，与同资金来源、模型成本群及授权等级的个人/同类基线比较。
- `spend_acceleration = current_rate / max(baseline_rate, epsilon)`；`epsilon` 为明确的最小成本单位，每种单位分别配置。
- 记录赠额领取到消耗时间、5 分钟/24 小时赠额使用比例、退款后再次尝试、成本与产出异常关系。

个人消耗基线取前 28 天同小时附近的可比 5 分钟桶中位数，排除最近 24 小时、异常/隔离样本与当前窗口；至少 7 个可比活跃日、30 次确认结算。以保守滞后方式更新，避免攻击持续后被学成正常。

QUOTA 候选规则：5 分钟实际消耗同时达到该套餐/单位的绝对门槛 `Q_min_cost`、个人基线的 5 倍和可用同类 P99，并伴随新设备或异常来源，暂停新资金预留 15 分钟。`Q_min_cost` 必须由定价与合法高频样本确定，未配置或基线不足只标记证据不足；新账号用明确的新账号预算与同类基线。

个人付费额度正常快速使用只触发预算/安全保护与核验，不据此认定套利。关联赠额套利须另有设备、领赠/邀请和消耗关系等相互印证证据。

### B：行为异常

**调用时间偏差。** 维护 24 个小时桶的请求分布，使用固定且有版本的时区口径，不随自报时区即时改变。个人时区不可用时统一使用 UTC；跨时区和作息变化进入解释信息。

基线来自前 28 天、排除最近 24 小时和已确认异常；最近分布取最近 24 小时。对各桶加 0.5 平滑，归一化为 P/Q，采用以 2 为底的 Jensen–Shannon divergence：`JSD(P,Q) = (KL(P||M) + KL(Q||M))/2`，`M = (P+Q)/2`，范围 0–1。历史至少 200 次请求、7 个活跃日，最近至少 50 次才输出该偏差；候选观察阈值 0.30。作息偏移本身仅观察。

**提示词重复程度。** 10 分钟至少 10 个独立有效文本操作后计算：

- 精确重复率：`1 - distinct(normalized_prompt_hmac) / text_operations`。
- 最大簇占比：`largest_prompt_cluster_operations / text_operations`。
- 近似重复率：可用时按版本化标签集合/分词相似度聚类；HMAC 相等只能表示相同规范化文本，形状摘要不能冒充语义相似度。
- 候选观察条件：精确重复率 ≥80%，或最大簇占比 ≥80%；若近似模型未接入，该项显示未知。

同时记录调用间隔中位数、离散程度、并发和连续活跃时长。反复改稿、固定模板、授权自动化和规律任务均可能正常。时间偏差、重复 Prompt 或固定节奏单独不自动封控；组合费用、明确违规或退避违背证据再处置。

### D：设备关联

区分第一方随机签名设备 Cookie、受信设备登记、公钥持有证明、浏览器辅助特征与客户端自报指纹。前者仍可能被复制，公钥持有不等于一台物理设备，UA/网络出口变化不算设备切换。

- `accounts_per_device_24h/7d`：相同有效设备标识下完成已鉴权操作的不同账号数。
- `devices_per_account_1h/24h`：同账号不同有效设备标识数。
- `device_switches_1h`：按受理顺序统计相邻有效设备 ID 的变化次数；A→B→A 为两次，重复 A→A 为零次。
- 补充并发设备数、首次设备时间、设备上关联受限账号比例及赠额使用关系；缺少设备 ID 的请求不虚构新设备。

候选阈值：同设备 24 小时 ≥3 个账号观察，≥5 个账号且存在协同领赠/消耗则冻结相关待发奖励并复核；同账号 1 小时 ≥5 个设备或 ≥8 次切换观察，叠加新 Key/异常消耗再限制相关会话。家庭、共享工作站和多设备创作者均需保留解释路径；不按一个客户端自报指纹连坐封禁。

### C：内容风险

- `content_block_ratio_30m = confirmed_content_denied_operations / reviewed_operations`，`reviewed_operations = confirmed_pass + confirmed_deny`；最低 20 个独立已审操作。
- `content_violation_count_10m/1h/24h`：明确违规操作次数，并按策略类别/严重程度分开。
- `violation_after_feedback_10m`：明确拒绝反馈发送后仍出现的新违规操作数。
- `near_retry_after_denial`：拒绝后相似内容、同类别变体、跨端点/Key 尝试；相似本身不是新的违规结论。

审核器、平台规则和上游审核分别标明来源。只有平台版本化策略采纳的高置信拒绝才进处罚计数；低置信结果转复核。未接入审核不得显示“拦截率 0%”，显示“未覆盖”。

候选规则沿用 V2：10 分钟 ≥5 次独立明确违规，其中 ≥3 次在明确反馈之后，暂停相关能力 30 分钟；30 分钟已审 ≥20、拒绝比例 ≥40%，且反馈后 ≥3 次新的明确违规，暂停 24 小时并复核。严重内容的当次禁止和专门规则独立生效，不意味着可以先违规数次。

### F：调用频率与资源占用

同时计算每 10 秒/1 分钟/5 分钟请求数、生成样本数、成本预算、在途数、排队数与队列占用时间。单次多图、超分和高成本模型不能只按“一次调用”计。

账户、Key、会话、模型/操作、通道和全站限额分别执行；合法高频用户按授权等级配置。新用户用明确的新账号策略，不把历史不足当异常。

并发和预算使用共享存储原子预留及有期限租约，出队再次核验限制。仅限制“账号+IP”组合会被换出口绕过，因此账号独立限制必须始终存在。共享 IP 的来源保护不能替代账号限制，也不能直接把学校/企业全体当成一个违规主体。

超合同速率直接 429/排队；异常程度作为评分参考。具体每分钟额度、并发和队列上限必须与套餐和实测容量一致，不能把现有风控观察阈值直接当全体用户的合同上限。

### E：失败、拦截后的持续尝试

把“操作失败次数”“明确违规次数”和“违背退避次数”分开统计：

- 普通上游失败/取消：不记账号违规；故障时由平台熔断，避免全站故障批量处罚用户。
- 参数错误、余额不足：10 分钟 ≥10 次独立无效请求，可对该 Key/会话短时限速 60 秒并提示修正；不能变成内容处罚。
- 明确内容拒绝：按 C 的违规口径计算；E 记录拒绝后的序列和跨入口规避，避免 C/E 对同一证据重复加分。
- 冷却期间重试：只统计已鉴权、反馈发送后且 `accepted_at < retry_at` 的新到达尝试；服务端自动重试不进入用户处罚计数。
- 429 后每分钟 ≥10 次独立到达且持续 2 分钟违背明确退避，可对该 Key/会话施加一次固定 5 分钟保护。仅写日志，不把这些拒绝重新计入内容违规或滚动续封。

处置实例固定 `starts_at`、`expires_at`、`max_expires_at`，同一实例内相同请求/规则不再次执行。到期前拒绝不刷新到期时间；到期后先允许有限试用，并按新发生的明确违规判断是否升级。客户端持续访问账号状态、帮助或申诉不算边界探测。

反复违规可按已完成且证据独立的案件在 7 天内递进 30 分钟→2 小时→24 小时；最高档转人工复核。硬预算、人工封禁和凭据撤销另行保持，不能随一般风险分衰减自动解除。相同事件既触发内容暂停又触发持续尝试时，合并对应能力处置，保留两个理由，不将时长简单叠加。

### N：高风险地区、代理与 VPN

地区风险采用管理员维护的版本化列表，记录依据、范围、更新时间和到期时间，不内置一个永久不变的国家黑名单。区域、ASN、数据中心、VPN、住宅代理、Tor、已确认恶意来源分别记录，不能互相推断。

每条网络情报保存供应商、查询时间、数据更新时间、有效期限和置信度。归属地和代理信誉使用独立可用性；`isVpn` 缺失为 unknown，不是 false。只使用可信入口确认的访问源 IP，忽略客户端自报代理/VPN 标签。

候选处置：单独命中地区/VPN/Proxy/Tor 仅观察或要求来源验证；命中恶意信誉且同时出现新设备、高额消耗、明显异常并发等独立证据时，强验证或暂停相关会话/Key 15 分钟。确认恶意来源可单独做入口保护，但不据此永久封禁该出口所有账号。缺失或过期情报不增加恶意分，也不宣称已检查安全。

## 5. 分数、置信度与处置

本表仅是生成调用场景的初始排序权重，不替代 V2 的账号接管、中转共享和注册套利场景模型。

| 维度 | Q 额度 | B 行为 | D 设备 | C 内容 | F 频率 | E 持续尝试 | N 网络 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 权重 | 20% | 15% | 15% | 20% | 10% | 15% | 5% |

每维 0–100，证据附置信度 c。按已覆盖维度输出排序分 `S = sum(w*c*s) / sum(w*c)`，同时输出 `coverage = sum(w for available dimensions)` 和完整缺失原因。低覆盖不能被标成可信低风险；覆盖率 <70% 时不使用综合分自动升级处罚，仍执行独立硬约束和高置信明确规则。

同一原始事件在 C/E、F/B 等多个维度出现时允许展示，但评分时按证据族设置贡献上限，不重复认定为两个独立异常。B、D、N 的弱信号不能通过反复出现或时间累积自动“洗成”高置信证据。

候选分层：0–29 正常，30–49 观察，50–69 结合独立证据强验证/降并发，70–84 对受影响能力临时冷却，85–100 高优先级隔离与复核。综合分自动动作还须满足：覆盖达标、至少两个相互独立的证据族，且至少一个为服务器确认的额度异常、明确内容违规、批准限额超出或退避违背。纯行为/设备/网络组合只观察或验证。明确的单维保护按自己的规则执行。

证据按事件与规则窗口去重，当前分重算而非无限累加。一般行为/网络观察证据可用 24 小时半衰期衰减；内容案件按 7 天追溯窗口保留并复核。分数衰减不会修改案件事实、有效处置或资产账本。误报结案移除其评分贡献并保留审计。

## 6. 状态机与响应

正常 → 观察 → 验证/限速 → 临时暂停 → 到期有限试用 → 恢复；独立硬规则可直接进入对应暂停。已确认泄露则另走凭据撤销/恢复流程。管理员永久处置需独立权限和复核。

处置按 `(主体, 能力, 规则, 处置实例)` 记录，含证据、操作者/自动来源、策略版本、执行回执、到期与恢复条件。固定期限暂停到期自动复核，避免同一请求无限续封。人工解除只撤销对应实例，不覆盖其他有效限制。

建议响应包含稳定错误码、用户可执行的下一步、服务端 `request_id` 和可公开的 `retry_at`/`Retry-After`；后台保存实际规则证据，用户响应不暴露设备关联账号、内部阈值或情报细节。429 表示短时速率/冷却，403 表示能力暂停/明确策略拒绝，503 表示必需审核/准入服务不可用，三者分别统计。

预算、账号封控等必要状态无法确认时停止受保护的付费操作；可选网络情报失败按 unknown 处理。内容服务不可用时对配置为必审的能力暂停新生成；避免用未审请求当成功审核样本。

## 7. 实施顺序与代码接入

| 阶段 | 交付 | 接入位置与验收前提 |
| --- | --- | --- |
| P0 事实链 | 统一地址解析、身份、操作 ID、结果分类、响应反馈和成本单位；限制与事件幂等 | `request-audit.ts`、`risk-ip.ts`、`risk-settlement.ts`；先证明事件不重计、成本可对账 |
| P0 资源保护 | 共享账号/Key 速率、并发/预算预留、队列出队复查、固定冷却 | `rate-limit.ts`、`model-concurrency.ts`、额度入口；多进程及重启测试 |
| P1 即时规则 | Q/F/E 特征与规则；设备登记及 D 观察；七维特征覆盖与影子决策 | 扩展 `risk-control.ts` 或拆成特征/策略/执行模块；不再让存量累计分永久限流 |
| P1 数据接入 | 版本化内容审核与明确上游拒绝适配、网络情报与 TTL | C/N 在未接入时显示未覆盖；测试未知错误和审核服务故障 |
| P2 行为与运营 | B 个人基线、近似聚类、可信关联图谱、复核/申诉及分组自动执行 | 基线样本和数据保留达到要求，经过回放与分组校准 |

统一准入覆盖站内生成/操作/超分、个人供应商、NewAPI 图像模型、OpenAI 兼容和 NAI 原生入口，包含回退通道；具体改动沿 `src/app/api/images/*`、`src/lib/provider/image-generation.ts`、`src/lib/compat-api.ts` 梳理。入口前置的 429 也进入资源事件，不能因为未到 `evaluateImageRisk` 就完全看不到持续冲击。

PostgreSQL 保存事实、设备关系、特征快照、处置与 outbox；Redis 或具备同等原子语义的共享存储保存速率、预算预留及租约。跨服务封控带版本和执行回执。退款、超时执行不明和部分产出继续走独立幂等结算，不以风控判定替代财务事实。

后台扩展现有风控策略面板：每维开关、阈值、适用用户组、观察/验证/限速/暂停动作、最长处置时间、灰度范围、版本与回滚。用户详情展示七维当前值/基线/覆盖率、命中证据、反馈后尝试时间线、设备关联、成本分来源和处置到期时间。完整 IP、跨账号设备关系及提示词原文各设权限，默认展示 HMAC、类别和摘要，配置保留期。

先影子计算并回放合法高频、创作改稿、企业共享出口及已确认异常样本；收集明确违规、独立操作、处置执行和申诉结果。按场景监测误报、阻止消耗、正常高频通过率、特征覆盖率、决策延迟与解除及时性，再启用分组自动动作。

## 8. 验收用例

1. 同请求、同幂等操作和后台事件重放不重复计费、计违规、加分或延长冷却；同键换正文不能复用旧结果。
2. 账号切换 IP/Key/端点后，账号预算和有效能力暂停仍生效；跨进程并发不能超预留上限。
3. 上游全站 5xx、超时、审核不可用、余额不足和普通 429 不进入内容违规比例，故障重试不批量惩罚账号。
4. 10 分钟明确拒绝达到规则且反馈后持续违规时触发内容暂停；反馈前已在途请求不当作无视拒绝。
5. 到期前自动重试不会无限续封；到期后有限试用恢复；新发生且独立确认的违规才触发后续升级。
6. 5 分钟费用突增须同时满足绝对量、可用基线与组合证据；从 0 到 1、正常批量付费创作和退款回写不误判套利。
7. 不同币种、图包与 AFF/Anlas 不混加；扣费、退款、部分产出和在途预留能对账，未确认成本不填 0。
8. 作息变化和高度重复的正常改稿只观察；基线不足、被截断、过期或被攻击污染时不输出确定偏差。
9. 同设备多账号与同账号频繁换设备均可观测；UA 更新、共享出口、自报指纹碰撞不导致关联账号自动封禁。
10. VPN/地区标签单独不永封；缺失 VPN 数据显示 unknown；伪造 `X-Forwarded-For`、`X-Real-IP` 或自报 VPN 头不能改变风控事实。
11. 重复提示词跨账号规则不反复给相关案件累加到 100；分数衰减不恢复已撤销 Key 或覆盖人工封禁。
12. 全部生成/操作/回退路径和队列出队检查同一处置；进程重启、事件重放、执行同步失败均有可验证结果。
13. 审核未覆盖时不显示 0% 违规；综合分同时显示覆盖率，缺失数据不能被包装为安全。
14. 后台能解释每次限制的证据、范围、到期和恢复条件；解除、误报、策略变更及敏感证据访问均留审计。
